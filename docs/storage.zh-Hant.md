# 多儲存與檔案遷移

[English](storage.md) · [简体中文](storage.zh.md) · [繁體中文](storage.zh-Hant.md) · [日本語](storage.ja.md) · [한국어](storage.ko.md) · [Français](storage.fr.md) · [Español](storage.es.md)

mihonban 把曲庫後設資料和檔案儲存分開。D1 記錄每張專輯屬於哪個命名後端，音訊和原圖仍放在對應儲存中。

## 資料模型

| 欄位/表 | 含義 |
|---|---|
| `storages` | 命名 OneDrive、WebDAV、Google Drive 或 Node 本地後端 |
| `albums.storage_id` | 專輯目錄所在後端；必須有值 |
| `artists.storage_id` | 藝人頭像所在後端 |
| `storages.is_write` | 新上傳使用的唯一命名目標；上傳前必須選擇一個 |

曲目和內頁圖使用儲存相對路徑並繼承專輯後端。藝人頭像有獨立繫結，因為同一藝人可能跨多個盤。

## 支援矩陣

| 後端 | Cloudflare | Node | 播放路徑 |
|---|---:|---:|---|
| OneDrive | 支援 | 支援 | 臨時直鏈，通常 302 |
| WebDAV | 支援 | 支援 | 主 Worker Range 代理 |
| Google Drive | 支援 | 支援 | 主 Worker Range 代理 |
| 本地資料夾 | 不支援 | 支援 | Node Range 流 |

把 API 從 Node 遷到 Cloudflare 前，必須先把繫結本地資料夾的專輯遷到雲後端，否則只有後設資料能恢復，音訊無法播放。

## 寫入目標

切換寫入目標隻影響之後的新上傳，不會移動舊專輯。讀取可以同時跨很多後端。

沒有後端 `is_write = 1` 時禁止上傳；寫入目標同時最多一個。

## 專輯遷移

遷移一張專輯時，Worker 會：

1. 收集曲目、封面、內頁，以及屬於同一源後端的藝人頭像。
2. 按相同相對路徑複製到目標。
3. 所有必需檔案成功後才更新 `albums.storage_id`。
4. 改綁已複製頭像並清理圖片映象索引。
5. 保留原始檔。

整庫遷移重複同一可恢復流程，已經在目標上的專輯會跳過。重新整理頁面只會停止後續迴圈，不會回滾已完成專案。

## 重要限制

- 只複製位元組，不改音訊 tag 或目錄結構。
- 不自動刪除原始檔。
- 大檔案經代理跨盤會消耗 Worker 請求和執行時間，大庫應分批。
- R2 是圖片映象，不是音訊後端。
- 資料庫遷移不會搬檔案；恢復後的後端必須存在相同相對路徑。

## 實用策略

| 目標 | 做法 |
|---|---|
| 擴容 | 新增後端並設為寫入目標，舊專輯保持原位 |
| 整庫換盤 | 新增並測試目標，整庫遷移，抽查後再歸檔源盤 |
| Node 本地盤搬到 Cloudflare | 在舊 Node 服務仍執行時新增雲後端，先遷完本地繫結，再匯出 D1 |
| 檔案遷移回滾 | 遷回已測試的舊後端；源副本通常仍在 |

## 備份關係

管理後臺設定備份包含 `storages` 及其憑據，但不包含專輯或音訊，必須按金鑰檔案保護。

預設資料庫匯出不含儲存配置，但會保留專輯/頭像的 `storage_id`。匯入 D1 後再恢復設定 JSON，原 ID 才會重新對應正確後端。

完整順序見 [database-migration.zh.md](database-migration.zh-Hant.md)。

## 遷移後驗收

- 在後臺測試目標後端。
- 播放一首小檔案和一首大檔案，並拖到接近結尾。
- 檢查封面、頭像和內頁。
- 確認專輯顯示目標後端。
- 獨立備份和恢復演練完成前不要刪原始檔。

## 排障

| 現象 | 原因/檢查 |
|---|---|
| 後端刪不掉 | 仍有專輯繫結 |
| 後設資料正常但播放 502 | 後端 ID/憑據缺失，或同路徑檔案未複製 |
| 遷移後頭像失效 | 檢查 `artists.storage_id` 和擁有頭像的源專輯 |
| Cloudflare 不能讀本地後端 | 預期行為，本地資料夾僅 Node 可用 |
| 大檔案遷移中斷 | 從返回的 `fileIndex` 重試，或在 Worker 外搬檔案並保持路徑 |
