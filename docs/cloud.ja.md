# アーキテクチャと実行モデル

[English](cloud.md) · [简体中文](cloud.zh.md) · [繁體中文](cloud.zh-Hant.md) · [日本語](cloud.ja.md) · [한국어](cloud.ko.md) · [Français](cloud.fr.md) · [Español](cloud.es.md)

Mihonban は、ローカル環境とクラウド環境で同じ React フロントエンドと Worker 互換 API を使用します。永続化とファイルアクセスのアダプターだけが実行環境に応じて変わります。

## 構成要素

| 構成要素 | Node | ローカル Wrangler | Cloudflare | データ上の位置づけ |
|---|---:|---:|---:|---|
| React アセット | はい | はい | はい | 再構築可能 |
| Hono API | はい | はい | はい | ステートレスなアプリケーション層 |
| カタログデータベース | SQLite | ローカル D1 | リモート D1 | メタデータの正本 |
| レート制限／キャッシュ KV | SQLite アダプター | ローカル KV | Cloudflare KV | 再構築可能 |
| R2 イメージミラー | 任意 | 任意のバインディング | 任意 | 再構築可能な画像キャッシュ |
| ローカルフォルダー | はい | いいえ | いいえ | 設定時はファイルの正本 |
| OneDrive／WebDAV／Google Drive | はい | はい | はい | ファイルの正本 |
| Python コンパニオン | 外部プロセス | 外部プロセス | 外部プロセス | 任意のローカルワークフロー |

音声ファイルは D1、KV、R2 画像キャッシュ、Git のいずれにも保存されません。

## リクエストパス

```text
Browser --HTTP/HTTPS--> API runtime
                         |-- catalog metadata: SQLite or D1
                         |-- short cache/rate limit: KV adapter
                         |-- image mirror: optional R2
                         +-- named storage backend

OneDrive temporary URL ---------> usually 302 direct playback
WebDAV / Google Drive ----------> main API Range proxy
Node local folder --------------> Node Range stream
Optional external proxy --------> signed five-minute relay for temporary URLs
```

外部プロキシは、メインAPIが一時的なURLを取得できるソースのみを受け取ります。WebDAV、Google Drive、ローカルフォルダの認証情報は一切受け取りません。

## 認証と役割

- リスナーパスワード（初期値は `APP_PASSWORD`）：閲覧と再生。
- 管理者パスワード（初期値は `ADMIN_PASSWORD`）：すべての書き込み操作とインフラ設定。
- パスワード不要ゲストモード：管理画面で明示的に有効にすると、パスワードなしでリスナー権限を付与します。
- コンパニオンキー（`COMPANION_KEY`）：ローカルの Python コンパニオンが使用する任意の `X-Api-Key`。

Adminで変更されたパスワードはPBKDF2ハッシュとして保存され、ブートストラップ環境の値よりも優先されます。パスワードを変更するとセッションエポックが増加し、既存のログインクッキーが取り消されます。ログイン失敗はソースIPごとにカウントされます。6回の失敗でそのソースは15分間ロックされます。

本番環境のクッキーにはHTTPSが必要です。`DEV_INSECURE_COOKIE=1`は信頼できるローカルHTTPテストのためだけに存在します。

## データモデル

- `albums`:アルバムのメタデータ、名前`storage_id`、隠された状態、順序フィールド。
- `tracks`:トラックのメタデータとストレージ相対パス;トラックはアルバムのバックエンドを継承します。
- `artists`:アーティストメタデータ、隠れた状態、アバターパス、独立アバター `storage_id`。
- `album_images`：アルバムバックエンドのギャラリーパスと、外部画像インポートを冪等にする任意の安定したソース識別子。
- `favorites`:アルバムやトラックのお気に入りと順番。
- `notes`:アルバムノート、アーティストノート、バイオグラフィー。
- `storages`:名前付きOneDrive、WebDAV、Google Drive、またはNodeローカル構成。
- `settings`:パスワードハッシュ、モジュールフラグ、R2設定、ソース設定、その他のruntime状態。
- `source_posts`、`track_imports`、画像キャッシュテーブル:運用メタデータ。

トラック名の正本は明示的に管理されます。管理画面でトラック名を変更すると `tracks.title_override` が設定され、その後のローカルコンパニオンによるスキャン、アルバム全体の再登録、単一トラックの同期でもその名前が保持されます。通常のトラックは引き続きファイルタグに従います。既存の D1 にはこの列が自動追加されます。移行前の行は次回登録時に分類され、同じ値なら通常の同期タイトルとなり、異なる場合はデータ損失を避けるため現在の D1 タイトルを手動変更として保持します。SQLite／D1 の論理バックアップにもこのフラグが保存されます。

管理者設定のJSONは、許可リストに記載された設定のサブセットと名前付きストレージ構成(認証情報を含む)をエクスポートします。カタログ行、パスワードハッシュ、古いセッションは除外します。暗号化して保存してください。

## アップロードと再生

- 新しいアップロードの書き込み対象として、単一の名前付きバックエンドが選択されます。
- 既存のアルバムは独自のアルバム`storage_id`を保持します。書き込みターゲットを変更しても、アルバムは移動しません。
- OneDriveアップロードセッションと一時的なダウンロードURLを使用します。
- WebDAVおよびGoogle Driveのアップロード/ストリームはメインAPIを通過します。
- NodeローカルフォルダファイルはNode runtimeのみでストリーミングされます。
- ウェブアップロードは、保存先が報告する正確なバイト数が期待値と一致した場合にだけ受理されます。再開可能なサービスは一時障害後に確定済みオフセットを取得して続行し、プロキシ型サービスはリクエスト本文全体を再送します。
- Rangeおよび`Content-Range`の挙動は、特にiOS上で信頼性の高いシーキングのために必要です。

## 画像

R2 を使わない場合、API は画像を所有するストレージから読み込み、エッジ／ブラウザー向けのキャッシュヘッダーを付けます。R2 を有効にすると、初回リクエストまたはプリウォーム時に画像をミラーへコピーし、以降のリクエストを公開 URL へリダイレクトできます。画像を置き換えるとインデックスが無効化され、再度ミラーリングできます。D1 のインデックスが失われても同じ公開 R2 オブジェクトが残っている場合、プリウォームは回数を制限した HEAD 確認でそのオブジェクトを再登録し、画像データを再ダウンロード／再アップロードしません。

公開 R2 画像へのリダイレクトはブラウザーと Cloudflare エッジで 5 分間キャッシュされ、stale-while-revalidate も有効です。リダイレクト先はバージョン付きで不変の R2 URL なので、ライブラリを更新してもカバーごとに Worker が再実行されません。カバーを交換した場合もキャッシュ期間後に反映されます。非表示画像と音声のリダイレクトは引き続き非公開・キャッシュなしです。

アルバム一覧や小さなアートワーク表示では、Cloudflare Image Transformations を使って保存済みの元画像から 256 px または 640 px の WebP 派生画像を生成します。`fit: scale-down` により、更新が遅れることのあるストレージ側のサムネイルキャッシュに頼らず、手動または Discogs で決めた構図を正確に保ちながら、スクロール中に数 MB の元画像をデコードする処理を避けます。詳細表示と切り抜き画面では引き続き元画像を使用します。R2 は変換元の `art:<album-id>:original` を保持し、`art:<album-id>:256` と `art:<album-id>:640` も保存します。変換を利用できない場合は元画像を返しますが、派生画像のキーには登録しません。

公開ミラーへのリダイレクト先が欠落または古いオブジェクトだった場合、Web アプリは所有ストレージから再取得します。Worker は画像バイトを検証し、必要ならプロバイダーのサムネイルから元画像へフォールバックします。復旧に成功すると、R2 オブジェクトとバージョン付き D1 インデックスを自動修復します。これにより、ブラウザーにキャッシュされた古い 404 は自己修復され、非公開ストレージの認証情報がブラウザーへ渡ることもありません。

R2 は音声バックエンドでも、カタログデータベースでもありません。

## 実行時スキーマと D1 上限

Worker は API リクエストを処理する前に古いカタログを更新します。公開 Wrangler テンプレートの安定した `DB_SCHEMA_KEY` を使い、更新成功時に現在のコードの実行時バージョンを `settings.schema_version` へ記録します。同じ isolate の後続リクエストはメモリ状態を使い、コールドスタートした isolate もこの 1 行だけを読み取って互換 DDL とバックフィルを省略します。`DB_SCHEMA_KEY` は安定したままにし、このマーカーを通常の整理で削除しないでください。リリースで実行時マイグレーションを追加する場合、保守担当者は `RUNTIME_SCHEMA_VERSION` も更新する必要があります。

同じ名前付きストレージ内では、アルバムフォルダーと曲パスの同一性を大文字・小文字を区別せず判定します。カタログ全体のアーティストも同じ規則です。最初に保存した表示上の綴りは保持しますが、大文字・小文字だけが異なる後続の重複は拒否します。

Workers Free の D1 は現在、1 日あたり読み取り 500 万行、書き込み 10 万行までを含み、00:00 UTC にリセットされます。再デプロイやコード修正で既に計上された使用量を減らすことはできず、クエリが復旧してからもダッシュボードの集計が前の合計を表示し続ける場合があります。現在の稼働状態は、キャッシュなしの API リクエストまたは D1 への直接クエリと、各クエリの `meta.rows_read` / `meta.rows_written` で確認してください。ダッシュボードのバーは履歴用量であり、リアルタイムのロック表示ではありません。使用量が再び急増した場合は、デプロイ設定に `DB_SCHEMA_KEY` が残り、`settings.schema_version` が現在の Worker と一致していることを確認してください。最新の上限は [D1 の料金説明](https://developers.cloudflare.com/d1/platform/pricing/)を参照してください。

## 定期処理

Cloudflare では、Wrangler の Cron Trigger が 6 時間ごとの 17 分に実行されます。Node では `SOURCE_SCAN_HOURS` を使用します（既定値は `6`、`0` で無効）。ソーススキャンは対応する RSS／Atom／Blogger のタイトルとリンクだけを読み取り、音楽はダウンロードしません。

`mihonban watch`は違います。実際のローカル受信箱を監視し、7-Zip/beetsを呼び出します。そのディレクトリにアクセスできるコンピュータやNAS上で動作しなければならず、Cloudflare Workers内では動かせません。

## バックアップとリカバリー層

1. カタログ：SQLite 対応バックアップまたは D1 の論理 SQL エクスポート。
2. 設定：管理画面の設定 JSON。保存時は暗号化します。
3. 実行時シークレット：パスワードマネージャーまたはデプロイ先のシークレットストア。
4. 音声とオリジナル画像：ストレージ側で独立してバックアップ。
5. KV：再構築します。R2 画像インデックスは同じバケットを維持する場合だけ移行し、それ以外は既存の公開オブジェクトを再登録するかプリウォームで再構築します。

詳細は[データベースバックアップ、移行、回復](database-migration.ja.md)を参照してください。

## ホスティングの境界

Cloudflareの無料プランは個人ライブラリや少数のリスナーに適していますが、クォータや利用規約は変わります。APIリクエスト、D1行、KV操作、R2、プロキシ音声はすべてプラットフォームリソースを消費します。OneDrive一時的なURLは一般的にWorkerをバイパスします。WebDAV、Google Drive、ローカルNodeストリーム、有効なプロキシルートはそうではありません。

Workers は自宅 PC のフォルダーへアクセスできず、ファイルシステムのイベントを待ち続けることも、音声の変換、beets の実行、アーカイブの展開もできません。これらの処理には任意のローカルコンパニオンを使用してください。

## 診断

Cloudflare:

```bash
cd cloud/worker
npx wrangler tail
npx wrangler d1 execute mihonban --remote --config wrangler.local.jsonc \
  --command "SELECT COUNT(*) AS albums FROM albums"
```

ローカル Wrangler では、同じコマンドを `--local` 付きで実行します。Node では `DATA_DIR`、起動ログ、管理画面のシステム状態を確認してください。リフレッシュトークン、署名付き音声 URL、設定エクスポート、リクエストの認証ヘッダーをログへ出力しないでください。
