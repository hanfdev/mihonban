# 스토리지 백엔드와 파일 마이그레이션

[English](storage.md) · [简体中文](storage.zh.md) · [繁體中文](storage.zh-Hant.md) · [日本語](storage.ja.md) · [한국어](storage.ko.md) · [Français](storage.fr.md) · [Español](storage.es.md)

mihonban 카탈로그 메타데이터와 파일 저장을 분리합니다. D1 각 앨범을 소유한 이름 있는 백엔드를 알고 있습니다; 오디오와 소스 이미지는 그 백엔드에 남아 있습니다.

## 데이터 모델

| 필드/표 | 의미 |
|---|---|
| `storages` | 명명된 OneDrive, WebDAV, Google Drive 또는 Node 로컬 백엔드 구성 |
| `albums.storage_id` | 앨범 폴더가 포함된 백엔드; 필수 |
| `artists.storage_id` | 아티스트 아바타를 포함하는 백엔드 |
| `storages.is_write` | 새로운 업로드를 위한 단일 이름 있는 대상; 업로드 전에 하나를 선택하세요 |

트랙과 갤러리 경로는 상대적인 저장 경로입니다. 트랙은 앨범 백엔드를 계승하며; 갤러리 이미지도 앨범 백엔드를 사용합니다. 아티스트 아바타는 아티스트가 여러 디스크를 아우르기 때문에 고유한 바인딩을 가집니다.

## 지원되는 백엔드

| 백엔드 | Cloudflare | Node runtime | 재생 경로 |
|---|---:|---:|---|
| OneDrive | 예 | 예 | 임시 URL, 보통 302 |
| WebDAV | 예 | 예 | 메인 Worker Range 프록시 |
| Google Drive | 네 | 네 | 메인 Worker Range 프록시 |
| 로컬 폴더 | 아니요 | 예 | Node Range 스트림 |

로컬 폴더 바인딩은 API를 Cloudflare으로 옮긴 후에는 재생할 수 없습니다. 내보내기 전에 그 앨범들을 클라우드 백엔드로 옮기세요D1.

## 쓰기 대상

쓰기 목표를 변경하면 향후 업로드에만 영향을 줍니다. 기존 앨범을 이동시키지 않습니다. 읽기는 여러 개의 구성된 백엔드에 걸쳐 있을 수 있습니다.

백엔드가 `is_write = 1` 없으면 업로드가 거부됩니다. 한 번에 하나의 백엔드만 활성화될 수 있습니다.

## 앨범 이동

한 앨범을 위해 Worker:

1. 트랙, 커버, 갤러리 이미지, 그리고 동일한 소스 백엔드에 속한 아티스트 아바타를 열거합니다.
2. 각 객체를 목표물에 대한 동일한 상대 경로로 복사합니다.
3. 모든 필요한 복사본이 성공한 후에만 업데이트가 `albums.storage_id`.
4. 복사된 아바타를 다시 바인딩하고 이미지 미러 인덱스를 무효화합니다.
5. 소스 객체는 손대지 않게 남겨두는 것.

대량 마이그레이션은 동일한 재개 가능한 작업을 반복합니다. 이미 바인딩된 앨범은 건너뛸 수 있습니다. 페이지를 새로고침하면 완료된 앨범을 되돌리지 않고 클라이언트 루프를 멈춥니다.

## 중요한 제한 사항

- 마이그레이션 복사 바이트; 오디오 태그나 디렉터리 레이아웃을 다시 작성하지 않습니다.
- 소스 파일은 자동으로 삭제되지 않습니다.
- 대규모 프록시 기반 전송은 Worker 요청과 실행 시간을 소모합니다. 대규모 라이브러리를 배치로 이동합니다.
- R2 이미지 미러이지 오디오 백엔드가 아닙니다.
- 데이터베이스 마이그레이션은 파일을 이동하지 않습니다. 복원된 백엔드에도 동일한 상대 경로가 존재해야 합니다.

## 실질적인 전략

| 목표 | 절차 |
|---|---|
| 용량 추가 | 백엔드를 추가하고 쓰기 목표로 설정; 기존 앨범은 그대로 유지해 |
| 모든 것을 이동 | 대상 추가/테스트, 대량 마이그레이션, 재생 검증, 그리고 나중에 소스 아카이브 |
| 로컬 저장소Node Cloudflare으로 이동하세요 | Node 아직 실행 중일 때는 클라우드 백엔드를 추가하고 내보내기 D1전에 로컬 구속 앨범을 마이그레이션하세요 |
| 파일 이동 롤백 | 테스트된 백엔드로 이전하기; 소스 복사본이 이미 존재할 수 있음 |

## 백업 동작

관리자 설정 백업에는 `storages`와 그들의 자격 증명이 포함되어 있습니다. 앨범이나 오디오는 포함되지 않습니다. JSON은 비밀로 처리하세요.

기본 데이터베이스 익스포터는 스토리지 설정을 생략하지만 각 앨범/아바타 `storage_id`은 유지합니다. D1 가져온 후 관리자 JSON을 복원해서 해당 ID가 동일한 이름의 백엔드로 해석되도록 하세요.

전체 복원 명령은 [database-migration.md](database-migration.ko.md)를 참조하세요.

## 마이그레이션 후 확인

- 관리자 모드에서 대상 백엔드를 테스트합니다.
- 최소 한 개의 작은 트랙과 하나의 큰 트랙을 재생하세요; 끝부분 근처를 찾으세요.
- 표지, 아바타, 갤러리 이미지를 확인하세요.
- 앨범이 목표 백엔드를 보고하는지 확인해.
- 별도의 백업 및 복원 테스트가 성공할 때까지 소스를 유지하세요.

## 문제 해결

| 증상 | 원인/확인 |
|---|---|
| 백엔드는 삭제할 수 없습니다 | 하나 이상의 앨범은 여전히 묶여 있습니다 |
| 앨범 메타데이터는 정상이지만 스트림은 502 | 백엔드 ID 누락, 잘못된 자격 증명, 또는 같은 경로로 복사되지 않은 파일 |
| 앨범 마이그레이션 후 아바타가 고장 난다 | `artists.storage_id` 확인하고 해당 아바타를 소유한 앨범을 마이그레이션하세요 |
| 로컬 백엔드가 Cloudflare | 예상 완료; 로컬 저장소는 Node runtime |
| 마이그레이션은 큰 파일에서 멈춥니다 | 보고된 `fileIndex`에서 다시 시도하거나 파일을 Worker 밖으로 옮기고 같은 경로를 유지하세요 |
