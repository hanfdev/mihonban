# 일상 운영 가이드

[English](manual.md) · [简体中文](manual.zh.md) · [繁體中文](manual.zh-Hant.md) · [日本語](manual.ja.md) · [한국어](manual.ko.md) · [Français](manual.fr.md) · [Español](manual.es.md)

이 가이드는 도서관 관리자를 위한 것입니다. 경로와 URL은 선택한 runtime과 개인 설정에 따라 다릅니다.

## 진입 지점

| 진입 지점 | 목적 |
|---|---|
| 웹 앱 | 탐색, 재생, 검색, 즐겨찾기, 가져오기, 관리 |
| 로컬 인박스 | Python 동반자가 처리하는 선택적 폴더 또는 RAR/ZIP/7z 아카이브 |
| `mihonban` CLI | 진단, 인제스트, 모니터링, 동기화, 풀, 저장된 RYM 페이지 처리 |

Python 동반자와 데스크톱 플레이어는 웹 재생에 필요하지 않습니다.

## 권한 구분

- 리스너 비밀번호: 인증된 콘텐츠를 탐색하고 재생할 수 있습니다.
- 관리자 비밀번호: 업로드, 편집, 숨기기, 삭제, 즐겨찾기, 정렬, 인프라 구성
- 비밀번호 없는 게스트 모드: 비밀번호를 입력하지 않고도 선택적으로 읽기 전용 리스너 접근 가능.
- 동반 키: 선택적 로컬 파이프라인의 기계 자격 증명.

모든 헬퍼 스크립트는 비밀번호가 제공되지 않으면 무작위 비밀번호를 생성하며, 고정된 기본 비밀번호는 어디에도 없습니다. 로컬 개발 비밀번호는 스테이지 디렉터리의 `.dev.vars`에 있습니다.

관리자 오버라이드 환경 부트스트랩 값에 저장된 비밀번호. 두 비밀번호 중 하나를 변경하면 기존 세션이 취소됩니다.

## 재생 및 모바일 조작

- 기본 탐색 메뉴로 이동하면 대상 페이지의 맨 위에서 시작합니다. 현재 활성화된 로고나 탐색 항목을 다시 누르면 페이지 맨 위로 부드럽게 이동하며, 즐겨찾기의 앨범/곡 탭에도 같은 동작이 적용됩니다.
- 음량, 언어, 정렬 설정은 브라우저 origin별로 저장됩니다. 새 호스트 이름이나 사용자 지정 도메인을 열면 새 설정으로 시작하며, 저장된 음량이 없을 때 기본값은 100%입니다.
- 재생은 원래 탭/클릭 이벤트 안에서 시작되므로 Android Chrome이 소리 재생과 시스템 미디어 세션을 만들 수 있습니다. 지원되는 브라우저에서는 잠금 화면/알림에서 재생, 일시 정지, 이전/다음 곡, 탐색을 제어할 수 있습니다.
- 모바일에서는 표지나 미니 플레이어의 빈 영역을 누르거나 미니 플레이어를 위로 밀어 재생 화면을 엽니다. 앨범과 아티스트 링크는 각각 따로 누를 수 있습니다.
- 모바일 미니 플레이어에는 이전 곡, 재생／일시 정지, 다음 곡이 이 순서로 항상 표시됩니다. 셔플과 반복은 전체 재생 화면에서 사용할 수 있습니다.
- 북클릿 이미지를 바꾸는 동안 로딩 상태가 표시됩니다. 터치 기기에서는 좌우로 밀어 이전/다음 이미지를 볼 수 있습니다.
- 앨범 그리드는 뷰포트 주변의 표지를 미리 불러오고 디코딩이 끝날 때까지 차분한 자리 표시자를 보여 줍니다. 정밀 포인터를 사용하는 데스크톱 라이브러리에서는 대기 중인 표지의 밝기와 채도를 조금 낮추고, 마우스를 올리거나 키보드 포커스를 두거나 현재 재생 중일 때 원래 색으로 복원합니다. 1000 kbps 이상의 비트레이트는 간결한 `M` 표기를 사용하며, 값 위에 마우스를 올리면 정확한 kbps를 확인할 수 있습니다.

## 받은편지함 폴더와 아카이브

1. 사용 권한이 있는 앨범 폴더나 아카이브를 설정 `inbox`에 넣으세요.
2. `mihonban ingest --apply`로 `mihonban watch` 실행하거나 한 번 처리합니다.
3. 로그와 격리 보고서를 검토한다; 하드 실패는 절대 조용히 버려지지 않는다.
4. 클라우드 동기화가 설정되면 `mihonban cloud sync` 실행할 수 있습니다.

파이프라인은 직접 폴더, 하나의 아카이브, 중첩된 아카이브를 지원합니다. 부분적으로 복사된 파일은 열리지 않도록 처리하기 전에 변경되지 않은 세 번의 폴링을 기다립니다. 작업은 사적인 임시 영역에서 이루어집니다. 성공적인 소스 항목은 `_done`; 하드 실패와 그 보고서는 `_quarantine`로 이동합니다.

파이프라인은 일본어 파일 이름 인코딩을 추출, 복구, 메타데이터/태그 조직 실행, 라이브러리 레이아웃 정규화, API에 결과를 등록할 수 있습니다. 모호한 메타데이터는 수동 검토가 가능하도록 유지됩니다.

## 클라우드 소스 스캔과 로컬 감시

관리자 소스 모듈은 지원되는 RSS/Atom/Blogger 제목과 링크를 읽습니다. Cloudflare Cron이나 Node의 인터벌은 가정용 컴퓨터가 꺼져 있을 때도 실행할 수 있습니다. 음악을 다운로드하거나 압축 해제하지 않습니다.

`mihonban watch` 로컬 `inbox`, 영구 파일, 7-Zip, 그리고 비트에 대한 접근이 필요합니다. Windows, macOS, Linux 또는 NAS에서 실행하세요; Cloudflare Workers 내부에서는 실행할 수 없습니다.

## 웹 가져오기

1. 관리자로 로그인하고 가져오기를 엽니다.
2. 한 앨범에 속한 트랙을 선택해 아티스트, 제목, 연도, 파일명, 순서를 리뷰합니다.
3. 커버를 선택/크롭하고 의도한 쓰기 대상 저장소를 선택합니다.
4. 업로드를 시작하고 모든 트랙이 끝날 때까지 기다렸다가 페이지를 떠납니다.
5. 완성된 앨범을 열어 트랙을 재생한 뒤, 끝부분을 찾는다.

관리자는 아티스트 페이지에서 영문 / 로마자 이름을 편집할 수 있습니다. 이 아티스트 단위 값은 해당 아티스트의 모든 앨범에 적용되며 이후 컴패니언 동기화에서도 유지됩니다.

아티스트 페이지의 Discogs 기능은 일치하는 후보를 자동으로 검색합니다. 올바른 후보가 없으면 공식 `discogs.com/artist/...` URL을 붙여 넣어 직접 가져올 수 있으며, 가져오기 전에 사진과 소개를 미리 보고 선택할 수 있습니다. 아티스트 목록의 기본 순서는 앨범 수를 먼저 비교하고, 앨범 수가 같을 때만 참여 곡 수를 비교합니다. 참여 곡은 더 차분한 둘째 줄에 표시되며 앨범과 같은 가중치로 계산되지 않습니다.

앨범 편집기에서는 발매작 전체의 기본 아티스트 크레딧과 순서를 설정합니다. 곡 관리에서는 각 곡 옆의 아티스트 버튼으로 해당 곡만의 협업 크레딧을 지정할 수 있으며, 옵션을 끄면 앨범 아티스트 상속으로 돌아갑니다. 곡 크레딧은 검색, 플레이어, 시스템 미디어 정보에 사용됩니다. 게스트 아티스트 페이지는 실제 참여한 곡만 참여 곡으로 표시하고 앨범 전체를 그 아티스트의 작품으로 분류하지 않습니다. 컴패니언은 실제 다중 값 `artist` / `artistsort` 태그를 읽으며 쉼표나 세미콜론으로 이름을 추측해 나누지 않습니다.

웹 복사본이 로컬 라이브러리로 반환되어야 할 때만 `mihonban cloud pull`을 사용하세요. 클라우드 메타데이터가 기존 로컬 태그를 업데이트해야 할 때만 `--retag` 추가하세요.

컴패니언은 누락된 앨범을 다운로드하기 전에 `data_dir/state/cloud_pull_incomplete/`에 영구 마커를 기록합니다. 다운로드, 클라우드 상세 조회, 태그 복구, 필요한 업로드와 재등록이 모두 성공한 뒤에만 마커를 지웁니다. 중단 후 `.partial` 파일이 남은 디렉터리나 유효한 오디오가 전혀 없는 디렉터리는 완성된 앨범으로 오인되지 않고 자동으로 다시 시도됩니다. Rclone은 기존 `.partial` 바이트를 이어받지 않고 0바이트부터 다시 받으므로 느린 네트워크에서는 watcher와 연결을 계속 유지하세요.

## RYM 메타데이터

Mihonban Rate Your Music 요청을 자동화하지 않습니다. 브라우저에서 발매 페이지를 수동으로 저장하고, 앨범 페이지에 저장된 HTML을 가져오며, 저장 전에 평점, 투표 수, 주/부차, 디스크립터를 검토하세요. CLI는 저장된 페이지를 파싱, 매칭, 수동으로 대량으로 작성할 수 있습니다.

## Discogs

관리자는 릴리스나 아티스트를 검색하고 이미지, 장르/스타일, 소개문 가져오기를 미리 볼 수 있습니다. Cloudflare에서는 관리자 브라우저가 Discogs 공식 공개 API에 직접 연결하고 공개 메타데이터를 로컬에 캐시하여 Worker 공유 출구 제한을 피합니다. 관리자의 개인 토큰은 선택 사항이며 서버 측 대체 요청에만 사용되고 브라우저로 전송되지 않습니다. 검색 결과에 표지가 없으면 현재 보이는 후보만 캐시된 릴리스 상세 정보를 필요할 때 재사용해 표지를 채웁니다. 미리 보기 썸네일은 브라우저가 불러오는 Discogs 공개 이미지이며, 설정된 저장소로 실제 가져오는 파일은 계속 인증된 Worker를 거쳐 Discogs 호스트, 크기, 파일 서명 검사를 받습니다.

앨범 이미지 가져오기는 멱등성을 보장합니다. 같은 Discogs 릴리스의 이미지를 다시 가져오면 이미 등록된 이미지는 건너뛰며 중복 복사본을 만들지 않습니다.

## 즐겨찾기와 숨김 콘텐츠

- 관리자는 앨범이나 곡을 즐겨찾기에 추가하고 드래그하여 순서를 변경할 수 있습니다.
- 청취자는 관리자가 구성한 즐겨찾기 페이지를 볼 수 있지만 편집할 수는 없습니다.
- 숨긴 앨범, 곡, 아티스트, 숨김 콘텐츠에만 존재하는 장르, 이미지, 검색 결과 및 즐겨찾기 항목은 청취자 응답에서 제외됩니다.
- “숨김 항목 표시”는 관리자 전용 보기 상태이며 앨범, 곡, 아티스트 목록에서 공유됩니다.
- 헤더의 앨범 수도 같은 상태를 따르며, “숨김 항목 표시”를 켠 경우에만 숨긴 앨범을 포함합니다.
- 앨범 갤러리에서 이미지를 전환하면 이전 이미지는 즉시 사라집니다. 선택한 이미지가 준비될 때까지 로딩 표시를 보여 주며, 실패하면 명확한 오류 상태를 표시합니다.

숨김 상태를 변경한 뒤에는 관리자 화면만 확인하지 말고 별도의 청취자 세션에서도 검증하세요.

## 이름 있는 저장소

- 쓰기 대상은 이후의 새 업로드에만 영향을 줍니다.
- 기존 앨범은 계속 각자의 `storage_id`가 가리키는 스토리지에서 읽습니다.
- 마이그레이션은 필요한 객체를 복사하고, 필수 복사가 모두 성공한 뒤에만 바인딩을 변경합니다.
- 원본 객체는 자동으로 삭제되지 않습니다.
- 대량 이동 후에는 재생, 탐색, 커버, 아바타와 갤러리를 확인한 뒤 이전 복사본을 보관하세요.

[스토리지 백엔드 및 파일 마이그레이션](storage.ko.md)을 참고하세요.

## 관리 화면

- 시스템 상태: 앨범/트랙/저장 총계와 동반 하트비트.
- 비밀번호와 게스트 접근.
- 백업 및 복원 설정: 민감한 구성, 카탈로그 행이 아님.
- 이름 저장 백엔드와 쓰기 타겟.
- R2 이미지 미러와 예열.
- Discogs 토큰.
- 선택적 소스 스캔 및 오디오 프록시 모듈.

설정의 JSON에는 자격 증명이 포함되어 있습니다. 암호화된 금고에 저장하고 이슈, 채팅, 이메일, Git에는 절대 첨부하지 마세요.

## 백업 주기

| 언제 | 행동 |
|---|---|
| 주요 가져오기 후 | Node SQLite 백업하거나 SQL D1 내보내기; 두 번째 오디오 복사본이 존재하는지 확인하기 |
| 저장소/R2/모듈 변경 후 | 새로운 관리자 설정 JSON 내보내기 |
| 애플리케이션 업데이트 전 | 데이터베이스 + 설정 JSON + 현재 커밋/배포 식별자 |
| 주기적으로 | 파일 존재만 확인하는 대신 복원 테스트를 수행하세요 |

[데이터베이스 백업, 마이그레이션, 복구](database-migration.ko.md).

## 자주 사용하는 명령

```text
mihonban doctor
mihonban ingest --apply
mihonban watch
mihonban cloud sync
mihonban cloud pull
mihonban cloud pull --retag
mihonban rym parse
mihonban rym match
mihonban rym write --apply

cd cloud/worker && npm test
cd cloud/web && npm test && npm run build
```

## 문제 해결

| 증상 | 행동 |
|---|---|
| 받은 편지함은 아무 효과도 없어요 | 아이템이 지원되고 완전히 복사되었는지 확인하고, 한 명의 워처만 실행하며, `data_dir/logs` |
