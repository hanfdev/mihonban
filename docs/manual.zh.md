# 日常使用手册

[English](manual.md) · [简体中文](manual.zh.md) · [繁體中文](manual.zh-Hant.md) · [日本語](manual.ja.md) · [한국어](manual.ko.md) · [Français](manual.fr.md) · [Español](manual.es.md)

本文面向曲库管理员。具体路径和网址取决于选择的运行时及私有配置。

## 三个入口

| 入口 | 用途 |
|---|---|
| 网页应用 | 浏览、播放、搜索、精选、导入和管理 |
| 本机收件箱 | 可选，由 Python 伴侣处理文件夹或 RAR/ZIP/7z |
| `mihonban` CLI | 诊断、整理、守望、同步、拉回和处理手存 RYM 页面 |

Python 伴侣和任何桌面播放器都不是网页播放的依赖。

## 身份

- 听众口令：浏览和播放需要认证的内容。
- 管理员口令：上传、编辑、隐藏、删除、精选、排序和基础设施设置。
- 免密访客模式：可选，无需输入口令即可获得听众只读权限。
- 伴侣密钥：可选本机管线使用的机器凭据。

所有辅助脚本在未提供口令时都会随机生成口令，任何部署都不带固定默认口令。本地开发口令保存在暂存目录的 `.dev.vars` 中。

管理后台保存的口令优先于环境变量中的初始值。修改任意口令都会让已有会话失效。

## 播放与移动端交互

- 主导航进入目标页面时会回到顶部；再次点击当前已激活的 LOGO 或导航项，会平滑返回页面顶部。精选页内的“音盘 / 歌曲”标签也遵循同一规则。
- 音量、语言和排序偏好按浏览器 origin 分开保存。改用新的主机名或自定义域名后会得到一套新偏好；未设置音量时默认是 100%。
- 播放会在原始点击/触摸事件内启动，使 Android Chrome 能建立有声播放和系统媒体会话；浏览器支持时，锁屏/通知栏可播放、暂停、切换上一首或下一首，以及拖动进度。iOS Safari 耗尽已缓冲音频时，Mihonban 会冻结系统媒体时间轴，等音频重新达到可播放状态后再恢复，避免无声期间的系统进度提前走动。
- 移动端点击封面或迷你播放栏空白处，或向上滑动播放栏，都能打开播放界面；专辑和艺人链接仍可单独点击。
- 移动端迷你播放栏会按“上一首、播放/暂停、下一首”的顺序始终显示完整控制；随机和循环仍在完整播放界面中提供。
- 切换内页图时会先显示加载状态；触屏设备可左右滑动查看前后图片。
- 专辑网格会提前预载视口附近的封面，并在解码完成前保留克制的占位状态。已成功解码的封面会在筛选或排序时保持就绪；短暂的图片加载失败会经过少量延迟重试。使用精细指针的桌面端曲库会轻微降低静止封面的亮度和饱和度；悬停、键盘聚焦或当前播放时恢复原色。曲目码率达到 1000 kbps 后使用紧凑的 `M` 表示，悬停仍可查看精确 kbps。

## 收件箱文件夹和压缩包

1. 把有权使用的专辑文件夹或压缩包放入配置的 `inbox`。
2. 运行 `mihonban watch`，或用 `mihonban ingest --apply` 单次处理。
3. 查看日志和隔离报告；硬失败不会被静默丢弃。
4. 配置云端同步后运行 `mihonban cloud sync`。

管线支持直接文件夹、一次压缩和嵌套压缩。连续三次轮询大小/目录树不变后才开始处理，避免打开尚未复制完成的内容。处理在私有临时区进行；成功的原始收件项移入 `_done`，硬失败及报告移入 `_quarantine`。

管线会解压、修复日文文件名编码、整理元数据/标签、规范曲库目录，并可向 API 登记结果。存在歧义的元数据保留给人工复核。

## 云端资源站扫描与本机守望

管理后台的资源站模块只读取支持的 RSS/Atom/Blogger 标题和链接。Cloudflare Cron 或 Node 定时器可以在家中电脑关机时运行它，但不会下载或解压音乐。

`mihonban watch` 需要真实本机 `inbox`、持久文件、7-Zip 和 beets，必须运行在 Windows、macOS、Linux 或 NAS 上，不能运行在 Cloudflare Workers 中。

## 网页导入

1. 管理员登录并打开“导入”。
2. 选择属于同一张专辑的曲目，核对艺人、标题、年份、文件名和顺序。
3. 选择/裁切封面，并确认目标命名存储。
4. 开始上传，等所有曲目完成后再离开页面。
5. 打开新专辑，播放一首并拖到接近结尾。

短暂断网不会让不完整的音频被悄悄登记。OneDrive 和 Google Drive 会在有限次数内重试并续传分块会话；WebDAV 等代理型上传会重新上传整个文件。Mihonban 会在登记专辑前核对存储端的精确文件大小，缺失或被截断的文件会明确报错而不会被接受。完成播放检查前请保留源文件。

管理员可在艺人页编辑英文 / 罗马音名称。这个艺人级名称会同步更新该艺人的所有专辑，并在后续伴侣同步时继续保留。

如果原名本身就是希望用于搜索和排序的名称，请将该字段留空。Mihonban 会保留这个空值，仅在搜索和排序时回退使用原名，而不会存储一份重复名称。

艺人页的 Discogs 功能会先自动搜索候选；如果没有正确结果，也可以粘贴官方 `discogs.com/artist/...` 链接直接读取，并在导入前预览、选择头像和简介。艺人总览默认先按音盤数排序，仅在音盤数相同时再比较参与歌曲数；参与歌曲会显示在较轻的第二行，不会与整张音盤等权计算。

专辑编辑器用于设置整张音盤默认的有序艺人署名；在“管理曲目”中，可用每首歌旁的艺人按钮设置仅该歌曲使用的合作艺人，关闭该选项即可恢复继承专辑艺人。歌曲署名会用于搜索、播放器和系统媒体信息。客席艺人的主页只会在“参与歌曲”中列出真正合作的歌曲，不会把整张音盤算作他的个人专辑。本机伴侣会读取真正的多值 `artist` / `artistsort` 标签，不会按逗号或分号猜测拆分艺人名。

多碟导入会保留每张碟的身份并分别显示标题。每张碟的曲目编号都从 1 重新开始；“管理曲目”只允许在同一张碟内调整顺序，不会因排序而改变碟号。

网页副本需要回到本机曲库时运行 `mihonban cloud pull`。只有希望云端元数据更新已有本地标签时才添加 `--retag`。

伴侣在下载每张本地缺失专辑前，会先在 `data_dir/state/cloud_pull_incomplete/` 写入持久标记；只有下载、读取云端详情、修复标签，以及必要的回传和登记全部成功后才清除。中断后留下 `.partial` 的目录，或完全没有有效音频的目录，会自动重试，不会再被误判为完整专辑。Rclone 重试旧 `.partial` 时会从第 0 字节重新下载，并不续传已有字节；网络较慢时应保持 watcher 和网络持续运行。

## RYM 元数据

Mihonban 不会自动请求 Rate Your Music。请在浏览器手动保存发行页 HTML，在专辑页导入，并检查评分、票数、主/副风格与 descriptors 后再保存。CLI 可以批量解析、匹配并写入用户手动保存的页面。

默认评分排序会按可信度加权，避免只有几次高分的小样本压过评分接近但拥有大量评价的作品。算法以 3.3 分为稳定先验、权重相当于 50 次评分，但不会修改数据库中保存或界面展示的 RYM 原始均分。需要严格按原始均分排序时请选择“评分（原始）”。

## Discogs

管理员可以搜索发行或艺人，预览后导入图片、genres/styles 和简介。在 Cloudflare 部署中，管理员浏览器会直连 Discogs 官方公开 API，并在浏览器本地缓存公开元数据，以避开 Worker 共享出口限流。管理后台的个人 token 是可选的，只供服务端备用请求使用，绝不会发送到浏览器。搜索结果缺少封面时，当前可见的候选项会按需复用已缓存的发行详情补载封面。预览缩略图是浏览器加载的 Discogs 公开图片；真正导入命名存储的图片仍经过已认证的 Worker，并接受 Discogs 域名白名单、大小和文件签名检查。

专辑内页图片导入具备幂等保护。再次导入同一 Discogs 发行的相同图片时，已经登记的图片会被跳过，不会生成重复副本。

## 精选与隐藏内容

- 管理员可以精选专辑或歌曲，并拖动排序。新加入精选的项目默认置于最前，便于立即找到；之后仍以人工排序为准。
- 听众只能查看整理好的精选页面，不能编辑。
- 隐藏专辑、曲目、艺人、只存在于隐藏内容的风格、图片、搜索结果和精选项都会从听众响应中移除。
- “显示已隐藏”是管理员专用视图状态，在音盘、歌曲和艺人列表间同步。
- 顶栏音盘数量遵循同一状态：只有开启“显示已隐藏”时才计入隐藏音盘。
- 专辑内页切换图片时会立即清除上一张图，在选中图片就绪前显示加载指示；请求失败则显示明确的错误状态。

修改隐藏状态后，应使用独立听众会话核验，不能只看管理员界面。

## 命名存储

- 写入目标只影响之后的新上传。
- 已有专辑继续从自己的 `storage_id` 读取。
- 迁移会复制必需对象，全部必需复制成功后才修改绑定。
- 不会自动删除源对象。
- 批量迁移后先测试播放、拖动、封面、头像和内页，再归档旧副本。

详见[多存储与文件迁移](storage.zh.md)。

## 管理后台

- 系统状态：专辑/曲目/存储数量和伴侣心跳。
- 口令与免密访客访问。
- 设置备份与恢复：敏感配置，不包含曲库行。
- 命名存储与写入目标。
- R2 图片镜像和预热。
- Discogs token。
- 可选资源站扫描和音源代理模块。

设置 JSON 含凭据，必须存放在加密保险库，不能附在 issue、聊天、邮件或 Git 中。

## 推荐备份节奏

| 时机 | 动作 |
|---|---|
| 每次重大导入后 | 备份 Node SQLite 或导出 D1 SQL；确认音频有第二份副本 |
| 每次改存储/R2/模块后 | 导出新的管理后台设置 JSON |
| 每次升级应用前 | 数据库 + 设置 JSON + 当前 commit/部署标识 |
| 定期 | 实际做恢复演练，而不只确认文件存在 |

详见[数据库备份、迁移与恢复](database-migration.zh.md)。

## 排障

| 现象 | 处理 |
|---|---|
| 收件箱没反应 | 确认输入受支持且复制完成、只有一个 watcher，并查看 `data_dir/logs` |
| 文件进入隔离区 | 阅读报告，检查损坏、压缩密码、不支持文件和匹配置信度 |
| 网页没有旧专辑 | 恢复曲库数据库；管理后台设置 JSON 不包含专辑 |
| 播放返回 502 | 测试专辑所属命名存储，并确认文件没有在 Mihonban 外被手动移动 |
| 进度在走但没有声音 | 检查播放器、浏览器标签页和系统输出音量；升级后强制刷新。新的浏览器 origin 默认音量为 100% |
| 进度拖动失败或 iOS 时长错误 | 检查上游/代理是否正确返回 206、`Content-Range` 和总长度 |
| 图片慢或 Graph 限流 | 测试并启用 R2，然后预热 |
| 卡片有封面但详情页封面失败 | 先强制刷新一次。当前版本会回源到所属存储并修复缺失的 R2 镜像；仍失败时分别测试该存储和 R2 |
| Google Drive 找不到旧文件 | 重新授权当前 Drive 权限并核对 root ID |
| 网页上传没有回到本机 | 运行 `mihonban cloud pull`，检查 rclone remote |
| 登录返回 429 | 停止重试并等待 15 分钟 |
| 本地 HTTP 登录不保持 | 设置 `DEV_INSECURE_COOKIE=1`；公网 HTTPS 绝不能设置 |
