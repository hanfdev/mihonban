# 日常使用手冊

[English](manual.md) · [简体中文](manual.zh.md) · [繁體中文](manual.zh-Hant.md) · [日本語](manual.ja.md) · [한국어](manual.ko.md) · [Français](manual.fr.md) · [Español](manual.es.md)

本文面向曲庫管理員。具體路徑和網址取決於選擇的執行時及私有配置。

## 三個入口

| 入口 | 用途 |
|---|---|
| 網頁應用 | 瀏覽、播放、搜尋、精選、匯入和管理 |
| 本機收件箱 | 可選，由 Python 伴侶處理資料夾或 RAR/ZIP/7z |
| `mihonban` CLI | 診斷、整理、守望、同步、拉回和處理手存 RYM 頁面 |

Python 伴侶和任何桌面播放器都不是網頁播放的依賴。

## 身份

- 聽眾口令：瀏覽和播放需要認證的內容。
- 管理員口令：上傳、編輯、隱藏、刪除、精選、排序和基礎設施設定。
- 免密訪客模式：可選，無需輸入口令即可獲得聽眾只讀許可權。
- 伴侶金鑰：可選本機管線使用的機器憑據。

所有輔助指令碼在未提供口令時都會隨機生成口令，任何部署都不帶固定預設口令。本地開發口令儲存在暫存目錄的 `.dev.vars` 中。

管理後臺儲存的口令優先於環境變數中的初始值。修改任意口令都會讓已有會話失效。

## 播放與行動端互動

- 音量、語言和排序偏好會按瀏覽器 origin 分開儲存。改用新的主機名稱或自訂網域後會得到一套新偏好；未設定音量時預設為 100%。
- 播放會在原始點擊/觸控事件內啟動，使 Android Chrome 能建立有聲播放和系統媒體工作階段；瀏覽器支援時，鎖定畫面/通知列可播放、暫停、切歌和拖動進度。
- 行動端點擊封面或迷你播放列空白處，或向上滑動播放列，都能開啟播放畫面；專輯和藝人連結仍可單獨點擊。
- 行動端迷你播放列會按「上一首、播放/暫停、下一首」的順序持續顯示完整控制；隨機和循環仍可在完整播放畫面中使用。
- 切換內頁圖時會先顯示載入狀態；觸控裝置可左右滑動查看前後圖片。

## 收件箱資料夾和壓縮包

1. 把有權使用的專輯資料夾或壓縮包放入配置的 `inbox`。
2. 執行 `mihonban watch`，或用 `mihonban ingest --apply` 單次處理。
3. 檢視日誌和隔離報告；硬失敗不會被靜默丟棄。
4. 配置雲端同步後執行 `mihonban cloud sync`。

管線支援直接資料夾、一次壓縮和巢狀壓縮。連續三次輪詢大小/目錄樹不變後才開始處理，避免開啟尚未複製完成的內容。處理在私有臨時區進行；成功的原始收件項移入 `_done`，硬失敗及報告移入 `_quarantine`。

管線會解壓、修復日文檔名編碼、整理後設資料/標籤、規範曲庫目錄，並可向 API 登記結果。存在歧義的後設資料保留給人工複核。

## 雲端資源站掃描與本機守望

管理後臺的資源站模組只讀取支援的 RSS/Atom/Blogger 標題和連結。Cloudflare Cron 或 Node 定時器可以在家中電腦關機時執行它，但不會下載或解壓音樂。

`mihonban watch` 需要真實本機 `inbox`、持久檔案、7-Zip 和 beets，必須執行在 Windows、macOS、Linux 或 NAS 上，不能執行在 Cloudflare Workers 中。

## 網頁匯入

1. 管理員登入並開啟“匯入”。
2. 選擇屬於同一張專輯的曲目，核對藝人、標題、年份、檔名和順序。
3. 選擇/裁切封面，並確認目標命名儲存。
4. 開始上傳，等所有曲目完成後再離開頁面。
5. 開啟新專輯，播放一首並拖到接近結尾。

管理員可在藝人頁編輯英文 / 羅馬字名稱。這個藝人層級名稱會同步更新該藝人的所有專輯，後續伴侶同步也會保留。

網頁副本需要回到本機曲庫時執行 `mihonban cloud pull`。只有希望雲端後設資料更新已有本地標籤時才新增 `--retag`。

伴侶在下載每張本機缺失專輯前，會先在 `data_dir/state/cloud_pull_incomplete/` 寫入持久標記；只有下載、讀取雲端詳情、修復標籤，以及必要的回傳和登記全部成功後才清除。中斷後留下 `.partial` 的目錄，或完全沒有有效音訊的目錄，會自動重試，不會再被誤判為完整專輯。Rclone 重試舊 `.partial` 時會從第 0 位元組重新下載，並不續傳已有位元組；網路較慢時應保持 watcher 和網路持續運作。

## RYM 後設資料

Mihonban 不會自動請求 Rate Your Music。請在瀏覽器手動儲存發行頁 HTML，在專輯頁匯入，並檢查評分、票數、主/副風格與 descriptors 後再儲存。CLI 可以批次解析、匹配並寫入使用者手動儲存的頁面。

## Discogs

管理員可以搜尋發行或藝人，預覽後匯入圖片、genres/styles 和簡介。在 Cloudflare 部署中，管理員瀏覽器會直連 Discogs 官方公開 API，並在瀏覽器本機快取公開中繼資料，以避開 Worker 共用出口限流。管理後臺的個人 token 為可選，只供伺服器端備用請求，絕不會傳送到瀏覽器。圖片下載仍經過已驗證的 Worker，並接受 Discogs 網域白名單、大小與檔案簽章檢查。

## 精選與隱藏內容

- 管理員可以精選專輯或歌曲，並拖動排序。
- 聽眾只能檢視整理好的精選頁面，不能編輯。
- 隱藏專輯、曲目、藝人、只存在於隱藏內容的風格、圖片、搜尋結果和精選項都不會出現在聽眾端。
- “顯示已隱藏”是管理員專用檢視狀態，在音盤、歌曲和藝人列表間同步。
- 頂欄音盤數量遵循同一狀態：只有開啟“顯示已隱藏”時才計入隱藏音盤。
- 專輯內頁切換圖片時會立即清除上一張圖，在選中圖片就緒前顯示載入指示；請求失敗則顯示明確的錯誤狀態。

修改隱藏狀態後，應使用獨立聽眾會話核驗，不能只看管理員介面。

## 命名儲存

- 寫入目標只影響之後的新上傳。
- 已有專輯繼續從自己的 `storage_id` 讀取。
- 遷移會複製必需物件，全部必需複製成功後才修改繫結。
- 不會自動刪除來源物件。
- 批次遷移後先測試播放、拖動、封面、頭像和內頁，再歸檔舊副本。

詳見[多儲存與檔案遷移](storage.zh-Hant.md)。

## 管理後臺

- 系統狀態：專輯/曲目/儲存數量和伴侶心跳。
- 口令與免密訪客訪問。
- 設定備份與恢復：敏感配置，不包含曲庫行。
- 命名儲存與寫入目標。
- R2 圖片映象和預熱。
- Discogs token。
- 可選資源站掃描和音源代理模組。

設定 JSON 含憑據，必須存放在加密保險庫，不能附在 issue、聊天、郵件或 Git 中。

## 推薦備份節奏

| 時機 | 動作 |
|---|---|
| 每次重大匯入後 | 備份 Node SQLite 或匯出 D1 SQL；確認音訊有第二份副本 |
| 每次改儲存/R2/模組後 | 匯出新的管理後臺設定 JSON |
| 每次升級應用前 | 資料庫 + 設定 JSON + 當前 commit/部署標識 |
| 定期 | 實際做恢復演練，而不只確認檔案存在 |

詳見[資料庫備份、遷移與恢復](database-migration.zh-Hant.md)。

```text
mihonban doctor
mihonban ingest --apply
mihonban watch
mihonban cloud sync

mihonban cloud pull --retag

mihonban rym write --apply

cd cloud/web && npm test && npm run build
```

## 排障

| 現象 | 處理 |
|---|---|
| 收件箱沒反應 | 確認輸入受支援且複製完成、只有一個 watcher，並檢視 `data_dir/logs` |
| 檔案進入隔離區 | 閱讀報告，檢查損壞、壓縮密碼、不支援檔案和匹配置信度 |
| 網頁沒有舊專輯 | 恢復曲庫資料庫；管理後臺設定 JSON 不包含專輯 |
| 播放返回 502 | 測試專輯所屬命名儲存，並確認檔案沒有在 Mihonban 外被手動移動 |
| 進度在走但沒有聲音 | 檢查播放器、瀏覽器分頁和系統輸出音量；升級後強制重新整理。新的瀏覽器 origin 預設音量為 100% |
| 進度拖動失敗或 iOS 時長錯誤 | 檢查上游/代理是否正確返回 206、`Content-Range` 和總長度 |
| 圖片慢或 Graph 限流 | 測試並啟用 R2，然後預熱 |
| 卡片有封面但詳細頁封面失敗 | 先強制重新整理一次。目前版本會回源到所屬儲存並修復缺失的 R2 映象；仍失敗時分別測試該儲存和 R2 |
| Google Drive 找不到舊檔案 | 重新授權當前 Drive 許可權並核對 root ID |
| 網頁上傳沒有回到本機 | 執行 `mihonban cloud pull`，檢查 rclone remote |
| 登入返回 429 | 停止重試並等待 15 分鐘 |
| 本地 HTTP 登入不保持 | 設定 `DEV_INSECURE_COOKIE=1`；公網 HTTPS 絕不能設定 |
