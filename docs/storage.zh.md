# 多存储与文件迁移

[English](storage.md) · [简体中文](storage.zh.md) · [繁體中文](storage.zh-Hant.md) · [日本語](storage.ja.md) · [한국어](storage.ko.md) · [Français](storage.fr.md) · [Español](storage.es.md)

mihonban 把曲库元数据和文件存储分开。D1 记录每张专辑属于哪个命名后端，音频和原图仍放在对应存储中。

## 数据模型

| 字段/表 | 含义 |
|---|---|
| `storages` | 命名 OneDrive、WebDAV、Google Drive 或 Node 本地后端 |
| `albums.storage_id` | 专辑目录所在后端；必须有值 |
| `artists.storage_id` | 艺人头像所在后端 |
| `storages.is_write` | 新上传使用的唯一命名目标；上传前必须选择一个 |

曲目和内页图使用存储相对路径并继承专辑后端。艺人头像有独立绑定，因为同一艺人可能跨多个盘。

## 支持矩阵

| 后端 | Cloudflare | Node | 播放路径 |
|---|---:|---:|---|
| OneDrive | 支持 | 支持 | 临时直链，通常 302 |
| WebDAV | 支持 | 支持 | 主 Worker Range 代理 |
| Google Drive | 支持 | 支持 | 主 Worker Range 代理 |
| 本地文件夹 | 不支持 | 支持 | Node Range 流 |

把 API 从 Node 迁到 Cloudflare 前，必须先把绑定本地文件夹的专辑迁到云后端，否则只有元数据能恢复，音频无法播放。

## 写入目标

切换写入目标只影响之后的新上传，不会移动旧专辑。读取可以同时跨很多后端。

没有后端 `is_write = 1` 时禁止上传；写入目标同时最多一个。

## 专辑迁移

迁移一张专辑时，Worker 会：

1. 收集曲目、封面、内页，以及属于同一源后端的艺人头像。
2. 按相同相对路径复制到目标。
3. 所有必需文件成功后才更新 `albums.storage_id`。
4. 改绑已复制头像并清理图片镜像索引。
5. 保留源文件。

整库迁移重复同一可恢复流程，已经在目标上的专辑会跳过。刷新页面只会停止后续循环，不会回滚已完成项目。

## 重要限制

- 只复制字节，不改音频 tag 或目录结构。
- 不自动删除源文件。
- 大文件经代理跨盘会消耗 Worker 请求和执行时间，大库应分批。
- R2 是图片镜像，不是音频后端。
- 数据库迁移不会搬文件；恢复后的后端必须存在相同相对路径。

## 实用策略

| 目标 | 做法 |
|---|---|
| 扩容 | 添加后端并设为写入目标，旧专辑保持原位 |
| 整库换盘 | 添加并测试目标，整库迁移，抽查后再归档源盘 |
| Node 本地盘搬到 Cloudflare | 在旧 Node 服务仍运行时添加云后端，先迁完本地绑定，再导出 D1 |
| 文件迁移回滚 | 迁回已测试的旧后端；源副本通常仍在 |

## 备份关系

管理后台设置备份包含 `storages` 及其凭据，但不包含专辑或音频，必须按密钥文件保护。

默认数据库导出不含存储配置，但会保留专辑/头像的 `storage_id`。导入 D1 后再恢复设置 JSON，原 ID 才会重新对应正确后端。

完整顺序见 [database-migration.zh.md](database-migration.zh.md)。

## 迁移后验收

- 在后台测试目标后端。
- 播放一首小文件和一首大文件，并拖到接近结尾。
- 检查封面、头像和内页。
- 确认专辑显示目标后端。
- 独立备份和恢复演练完成前不要删源文件。

## 排障

| 现象 | 原因/检查 |
|---|---|
| 后端删不掉 | 仍有专辑绑定 |
| 元数据正常但播放 502 | 后端 ID/凭据缺失，或同路径文件未复制 |
| 迁移后头像失效 | 检查 `artists.storage_id` 和拥有头像的源专辑 |
| Cloudflare 不能读本地后端 | 预期行为，本地文件夹仅 Node 可用 |
| 大文件迁移中断 | 从返回的 `fileIndex` 重试，或在 Worker 外搬文件并保持路径 |
