# Mihonban 네이티브 Windows 클라이언트

[English](README.md) · [简体中文](README.zh.md) · [繁體中文](README.zh-Hant.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Français](README.fr.md) · [Español](README.es.md)

이 디렉터리는 Rust로 작성한 네이티브 데스크톱 클라이언트입니다. `egui`로 자체 화면을 그리며 `reqwest`로 Mihonban HTTP API에 직접 연결하고, 지원되는 오디오 형식은 `rodio` / Symphonia로 로컬에서 디코딩합니다. 브라우저를 내장하거나 Mihonban 웹 앱을 불러오지 않습니다.

여러 Mihonban 서비스 프로필을 지원합니다. 서비스 주소는 설정에서 바꿀 수 있고 비밀번호는 Windows 자격 증명 관리자에 저장됩니다. 선택적인 클라이언트 업데이트 매니페스트는 Mihonban 서버 릴리스와 독립적입니다. 태그가 있는 빌드는 [GitHub Releases](https://github.com/hanfdev/mihonban/releases)의 `desktop-v*` 태그로 배포하며, 각 릴리스에는 포터블 exe와 SHA-256 체크섬 파일이 첨부됩니다.

## 화면, 설정 및 캐시

클라이언트는 Windows 배율과 작업 표시줄을 제외한 작업 영역을 따르며 해당 모니터에서 최대화하여 시작합니다. 시작 뷰포트에는 고정 내부 크기를 지정하지 않습니다. eframe 0.29가 최대화 창을 만든 뒤 그 크기를 적용하면 최대화 상태를 해제하지 않은 채 창만 작아질 수 있기 때문입니다.

연결 카드는 내용에 맞춰 크기를 조정하고 탐색 모음 아래 영역의 중앙에 머뭅니다. 번역문이나 오류 메시지가 높이를 바꿔도 동일합니다. 작은 서버 배지는 호스트, 포트, 배포 경로를 표시하고 도구 설명에는 전체 주소를 유지합니다. 연결에 실패하면 재시도와 설정을 바로 선택할 수 있습니다.

화면은 Mihonban의 어두운 아카이브／레코드 디자인을 따릅니다. 고정 헤더, 가운데 검색, 표지 모음, 앨범 소개와 트랙 목록, 상시 표시되는 네이티브 플레이어를 제공합니다. 표지와 오디오는 프로필별 영구 캐시를 사용합니다. 설정에서 캐시 폴더, 1–200 GB 한도, 현재 사용량, 캐시 삭제, 탐색기 바로가기를 제공합니다. 캐시는 원자적 쓰기와 최근에 가장 적게 사용한 항목을 제거하는 방식을 사용하며, 한도보다 큰 파일은 한 번 재생하고 보관하지 않습니다.

다른 트랙을 선택하면 교체되는 오디오 다운로드를 취소합니다. 재생 중지와 미리 가져오기 취소도 연결과 미완성 파일을 해제하며, 디스크 캐시가 꺼져 있어도 같습니다. 활성 캐시를 지우면 진행 중인 다운로드도 취소하여 나중에 다시 채워지지 않게 합니다. 완성된 파일은 재생에 사용할 수 있으며 미완성 다운로드는 작업 종료 또는 취소 시 정리합니다. 다른 프로세스가 미완성 파일을 잠시 잠그면 이후 시작할 때 10분 넘게 방치된 캐시 조각을 제거합니다.

아티스트 목록과 상세 화면의 사진은 가로세로 비율을 유지하며 중앙 기준으로 자릅니다. 가로 및 세로 사진에 적용되는 Web 클라이언트의 `object-fit: cover`와 같은 동작입니다.

Windows에서는 최소화하면 기본적으로 네이티브 시스템 트레이 아이콘으로 숨겨지고, 재생과 대기열 진행은 백그라운드에서 계속됩니다. 원래 Mihonban 아이콘을 두 번 클릭하거나 오른쪽 클릭 메뉴의 기본 창 표시를 선택하면 창을 복원합니다. 메뉴에는 재생／일시 정지와 종료도 있습니다. 설정 → 창 동작에서 최소화와 닫기 시 트레이로 숨기는 옵션을 각각 저장합니다. 닫기는 기본적으로 앱을 종료하고 트레이의 종료 명령은 항상 앱을 끝냅니다. 트레이 초기화가 실패해도 일반 창 동작은 유지됩니다.

기본 캐시는 Windows 로컬 앱 데이터 디렉터리에 있습니다. 폴더나 한도를 바꿔도 네이티브 클라이언트에만 적용되며 Mihonban 서버나 서버 저장소는 바뀌지 않습니다.

설정은 Windows 사용자별로 `%APPDATA%\Mihonban\Mihonban\config\config.json`에 저장합니다. 같은 계정에서 실행하는 모든 클라이언트 사본은 exe의 위치와 관계없이 같은 서비스 프로필, 창 환경설정 및 캐시 설정을 읽습니다. 비밀번호는 프로필 이름을 키로 사용하여 Windows 자격 증명 관리자에 별도로 보관합니다. 저장된 프로필이 없는 컴퓨터는 내장된 로컬 예시 주소로 시작합니다.

설정 화면은 라이브러리와 같은 따뜻한 검은색 표면, 세리프 제목, 얇은 테두리 및 주황색 작업 버튼을 사용합니다. 중앙 화면은 넓은 창에서 서비스 양식과 창／업데이트 사이드바로, 작은 창에서 전체 너비 카드의 세로 배치로 전환됩니다. 네이티브 입력 필드, 키보드로 조작하는 스위치, 줄바꿈되는 작업 영역 및 로컬 저장 용량 표시기는 7개 인터페이스 언어를 지원합니다. 캐시 활성화, 디렉터리, 크기 제한은 캐시 설정을 저장해야 적용되며 트레이 옵션은 계속 자동 저장됩니다.

서비스 카드에서 서버 프로필을 삭제할 수 있습니다. 확인 대화 상자는 저장된 프로필과 주소를 명시하고 취소를 기본값으로 하며 명시적인 두 번째 확인을 요구합니다. 최소 한 개의 프로필은 유지합니다. 선택된 프로필을 제거하면 다른 저장된 프로필로 전환하고 기존 재생을 중지하지만 서버 음악, 즐겨찾기 또는 로컬 캐시 미디어는 삭제하지 않습니다. 다른 프로필이 같은 자격 증명 이름을 쓰지 않는 한 저장된 자격 증명도 삭제합니다.

## 메모리와 라이브러리 성능

디스크 캐시와 디코딩된 이미지 메모리는 별도로 관리합니다. 표지와 아티스트 사진은 보이는 표지 수에 따라 변하는 LRU 텍스처 예산을 사용합니다. 범위는 40–72 MiB이며 200% 배율의 4K 화면을 포함합니다. 갤러리 이미지 예산은 16 MiB입니다. 다음 가시성 판정이 시작되기 전, 대기 중인 업로드는 이전 프레임에서 보이던 텍스처를 보존합니다. 제거 시 네이티브 텍스처 핸들을 해제하며 이미지를 다시 보면 디스크 캐시에서 불러옵니다. 보이는 갤러리／추천 카드만 이미지를 요청합니다. 이미지 다운로드, 디코딩 또는 대기 중인 디코딩 결과는 동시에 최대 두 개를 유지하며 디코딩과 크기 조정은 UI 스레드 밖에서 실행합니다. 표지와 사진은 비율을 유지하면서 512 px 이내로, 갤러리는 2048 px 이내로 제한합니다. 기존 표지 음영은 유지하지만 아티스트 사진에는 사용하지 않는 어두운 사본을 만들지 않습니다. 이 예산은 이미지 텍스처 데이터만 포함하며 전체 프로세스, 그래픽 드라이버, 글꼴 또는 디코딩 중 임시 할당은 포함하지 않습니다.

기존 로컬 미디어 캐시의 텍스처 예산을 네트워크 없이 확인하려면 저장소 루트에서 `cargo run --locked --manifest-path desktop/Cargo.toml --example texture_memory_probe -- <cache-directory>`를 실행합니다. 보고서는 실제 이미지 크기로 디코딩된 RGBA 데이터량을 추정하고 실제 LRU 정책을 시뮬레이션합니다. 프로세스 작업 집합 측정값은 아닙니다.

앨범 모음은 행을 가상화합니다. 뷰포트와 위아래 한 행만 카드 위젯을 만들고 같은 높이의 여백이 전체 스크롤 범위를 유지합니다. 필터나 라이브러리가 바뀔 때까지 필터링과 정렬은 공통 인덱스 목록을 재사용합니다. 연대, 아티스트, 장르 옵션은 라이브러리 데이터가 바뀔 때만 다시 만듭니다. 카드 상호작용 ID가 앨범 식별자를 따르므로 행이 화면에 들어와도 마우스 올림과 클릭 상태가 안정적으로 유지됩니다. 네이티브 부드러운 휠 입력, 카드 애니메이션 시간, 오른쪽 스크롤 막대 스타일은 그대로 유지합니다.

아티스트 페이지는 프레임 사이에 앨범 합계, 장르 선택지 및 검색 데이터를 재사용합니다. 아티스트 메타데이터 새로고침이나 서비스 프로필 변경은 스냅샷을 무효화하며, 앨범 또는 아티스트 수가 같게 유지되는 업데이트도 포함합니다. ASCII 대소문자만 다른 장르는 하나의 필터로 합치고 가장 자주 쓰이는 표기를 표시합니다. 현재 필터 결과만 유지하므로 새 검색어를 입력해도 검색 기록 캐시가 누적되지 않습니다.

트랙의 아티스트 표기가 앨범의 순서 있는 아티스트 크레딧과 정확히 같으면 중복 아티스트 줄을 생략합니다. 크레딧이 다른 트랙은 개별 아티스트 링크를 유지합니다. 다른 크레딧이 전혀 없는 앨범은 좁은 행을 사용하고 한 트랙이라도 두 번째 줄이 필요하면 모든 행의 높이를 동일하게 늘립니다. 갤러리와 유사 앨범 가로 목록의 스크롤 막대는 사용 가능한 행 전체 너비에 걸쳐 표시합니다.

디스크 캐시 적중 시 LRU 접근 시간을 메모리에서 갱신하고 다음 캐시 변경 때 저장하므로 이미지마다 전체 인덱스를 다시 쓰지 않습니다. 실패한 이미지는 30초 후 재시도하여 없는 표지에 대한 연속 요청을 막습니다. 저장소 루트에서 `cargo run --release --locked --manifest-path desktop/Cargo.toml --example scroll_layout_probe`를 실행하면 전체 그리드와 가상화된 egui 배치를 화면 없이 비교합니다. 이 합성 CPU 벤치마크는 보이는 카드와 스크롤 높이의 동등성을 검사하며 앱 FPS, GPU 렌더링, 이미지 디코딩 또는 휠 입력 지연은 측정하지 않습니다.

## 재생

플레이어는 Web 배치를 따릅니다. 작은 막대 한 줄에 표지, 트랙 정보, 재생 제어, 탐색 막대 및 음량을 표시합니다. 표지를 선택하면 흐린 표지 배경과 중앙의 두 열 구성, 재생 중 주황색 제어 버튼을 사용하는 지금 재생 화면을 엽니다. 곡 제목은 앨범을, 아티스트 이름은 아티스트 페이지를 열며 Escape는 지금 재생을 접습니다. 두 플레이어 보기 모두 Space로 재생／일시 정지를 전환합니다.

두 보기는 셔플, 반복 끄기／전체 반복／한 곡 반복 및 음소거를 공유합니다. 셔플은 대기열의 모든 곡을 한 번씩 재생한 뒤 중지하거나 반복하며 이전 곡은 그 순서를 되짚습니다. 탐색 막대를 끌 때 시간을 미리 보여 주고 놓을 때 이동을 확정합니다. 초점이 있는 탐색 막대는 방향키(5초, Shift와 함께 사용하면 30초)와 Home/End를 지원합니다. 음량도 방향키로 조작하며 음소거를 해제하면 이전에 들리던 음량으로 복원합니다.

오디오 파일에는 파일 정보를 받는 Rodio 디코더 생성자를 사용하여 전체 파일 길이와 탐색 가능 여부를 전달합니다. 따라서 탐색 표가 없는 FLAC에서도 위치 이동을 지원합니다. 재생 위치는 오디오 출력에서 직접 얻고, 탐색 실패는 짧은 알림으로 표시하며 임시 위치 덮어쓰기로 숨기지 않습니다. [탐색 회귀 테스트 자료](tests/fixtures/README.ko.md)는 탐색 표가 없는 생성 오디오를 포함하며 앞뒤로 탐색한 샘플을 순차 디코딩 결과와 비교합니다. 실제 오디오 출력과 완전한 로컬 파일로 추가 확인하려면 저장소 루트에서 `cargo run --locked --manifest-path desktop/Cargo.toml --example seek_backend_probe -- <audio-file> [<audio-file> ...]`를 실행합니다.

## 빌드 및 테스트

저장소 루트에서 최적화된 Windows 클라이언트를 빌드하고 실행합니다.

```powershell
cargo run --release --locked --manifest-path desktop/Cargo.toml
```

클라이언트 변경을 배포하기 전에 저장소 루트에서 `cargo test --locked --manifest-path desktop/Cargo.toml`를 실행하세요. 테스트는 로컬 HTTP 다운로드 중단, 곡 전환, 캐시 삭제와 제거, 아티스트 캐시 무효화 및 트랙 행 배치 회귀를 다룹니다. 두 합성 성능 벤치마크는 일반 테스트에서 제외되며 아티스트 집계 또는 제거 비용을 비교할 때는 `cargo test --release --locked --manifest-path desktop/Cargo.toml -- --ignored --nocapture`를 실행합니다. 시간 측정값은 알고리즘 비용이며 앱 FPS나 프로세스 메모리 측정값이 아닙니다.

릴리스 프로필은 실행 파일 크기를 줄이는 데 중점을 둡니다. 내장 글꼴은 릴리스 exe 안에 압축하고 시작 시 풀어 지원 언어와 음악 메타데이터의 타이포그래피를 유지합니다. Debug 실행 파일은 최적화되지 않은 개발 코드를 포함하므로 더 큽니다. Release 실행 파일은 Windows GUI 하위 시스템을 사용하여 터미널 창 없이 열립니다.

## 업데이트

선택적인 업데이트 원본 URL은 Windows 클라이언트 배포자가 제공합니다. 릴리스 채널이 없으면 비워 두세요. Mihonban 서비스 주소와 별개이며 서버를 업데이트하지 않습니다. 업데이트 확인은 버전 메타데이터를 읽고, 다운로드 및 검증은 사용자가 직접 교체하도록 새 exe를 준비하며 자동으로 설치하지 않습니다.

업데이트 원본은 클라이언트 릴리스 채널에서 호스팅하는 작은 JSON 문서를 가리킵니다. 예:

```json
{
  "latest": "0.2.0",
  "download_url": "https://github.com/hanfdev/mihonban/releases/download/desktop-v0.2.0/mihonban_desktop.exe",
  "sha256": "...",
  "notes": "..."
}
```

서버 요구 사항은 [네이티브 API 호환성 계약](API_COMPATIBILITY.ko.md), 서버 설치와 다른 클라이언트는 [프로젝트 안내](../README.ko.md)를 참고하세요.
