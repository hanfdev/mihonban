# Mihonban ネイティブ Windows クライアント

[English](README.md) · [简体中文](README.zh.md) · [繁體中文](README.zh-Hant.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Français](README.fr.md) · [Español](README.es.md)

このディレクトリには Rust 製のネイティブデスクトップクライアントがあります。`egui` で画面を描画し、`reqwest` で Mihonban HTTP API に直接接続し、対応する音声形式を `rodio` / Symphonia でローカルにデコードします。ブラウザーを組み込んだり、Mihonban の Web アプリを読み込んだりする方式ではありません。

複数の Mihonban サービスプロファイルに対応しています。サービス URL は設定で変更でき、パスワードは Windows 資格情報マネージャーに保存されます。任意のクライアント更新マニフェストは Mihonban サーバーのリリースと独立しています。タグ付きビルドは [GitHub Releases](https://github.com/hanfdev/mihonban/releases)（`desktop-v*` タグ）で公開され、各リリースにポータブル exe と SHA-256 チェックサムファイルが添付されます。

## 画面、設定、キャッシュ

起動時には、Windows の表示倍率とタスクバーを除いた作業領域に従い、そのモニター上で最大化します。起動ビューポートには意図的に固定の内部サイズを指定していません。eframe 0.29 は最大化ウィンドウの作成後にそのサイズを適用するため、最大化状態を解除せずにウィンドウだけ縮小する場合があるためです。

接続カードは内容に合わせて大きさを調整し、ナビゲーションバーの下で常に中央に配置されます。翻訳文やエラーで高さが変わっても同様です。小さなサーバーバッジにはホスト、ポート、配置パスを表示し、ツールチップには完全な URL を残します。接続に失敗した場合は、再試行と設定に直接進めます。

画面は Mihonban の暗いアーカイブ／レコード調のデザインを採用しています。固定ヘッダー、中央の検索、カバー一覧、アルバムの大きな紹介領域と曲一覧、常設のネイティブプレーヤーを備えます。カバーと音声にはプロファイルごとの永続キャッシュを使用します。設定でキャッシュフォルダー、1–200 GB の上限、使用量、消去、エクスプローラーで開く操作を管理できます。書き込みはアトミックに行い、最も長く使われていない項目から削除します。上限より大きいファイルは一度再生しても保存しません。

別の曲を選ぶと、置き換えられる音声のダウンロードを中止します。再生停止と先読みの中止でも接続と未完成ファイルを解放し、ディスクキャッシュが無効でも同じです。有効なキャッシュを消去すると進行中のダウンロードも中止し、後から再保存されることを防ぎます。完成したファイルは再生に利用でき、未完成ファイルはタスク終了時または中止時に整理します。他のプロセスが未完成ファイルを一時的にロックした場合、次回以降の起動で十分以上経過した放置キャッシュ断片を削除します。

アーティスト一覧と詳細画面の写真は、縦横比を維持して中央で切り抜きます。横長・縦長写真に対する Web クライアントの `object-fit: cover` と同じ動作です。

Windows では最小化時に標準でネイティブのシステムトレイアイコンへ隠れ、再生とキューの進行はバックグラウンドで続きます。Mihonban のオリジナルアイコンをダブルクリックするか、右クリックメニューの「メインウィンドウを表示」で復帰できます。メニューには再生／一時停止と終了もあります。設定 → ウィンドウの動作で、最小化時と閉じる時のトレイ格納を個別に保存できます。閉じる操作は標準では終了し、トレイの終了コマンドは常にアプリを終了します。トレイの初期化に失敗しても通常のウィンドウ操作は利用できます。

標準のキャッシュは Windows のローカルアプリデータフォルダーに置かれます。フォルダーや上限の変更はネイティブクライアントだけに適用され、Mihonban サーバーやその保存先は変更しません。

設定は Windows ユーザーごとに `%APPDATA%\Mihonban\Mihonban\config\config.json` に保存します。同じアカウントで実行するクライアントは、exe の置き場所に関係なく同じサービスプロファイル、ウィンドウ設定、キャッシュ設定を読みます。パスワードはプロファイル名をキーとして Windows 資格情報マネージャーに別途保存します。保存済みプロファイルがない端末では、内蔵のローカル仮アドレスから開始します。

設定画面もライブラリと同じ暖色寄りの黒い背景、セリフ体の見出し、細い枠線、オレンジの操作ボタンを使います。中央の画面は、広いウィンドウではサービスフォームとウィンドウ／更新のサイドバー、狭い場合は全幅カードの縦積みに切り替わります。ネイティブ入力欄、キーボードで使えるスイッチ、折り返す操作列、ローカル保存容量メーターは七言語に対応しています。キャッシュの有効設定、フォルダー、上限変更は保存後に適用され、トレイ関連の設定は引き続き自動保存されます。

サービスカードからサーバープロファイルを削除できます。確認ダイアログは保存名と URL を明示し、初期選択をキャンセルにして、もう一度明示的な確認を求めます。少なくとも一つのプロファイルを残します。選択中のプロファイルを削除すると別の保存済みプロファイルへ切り替わり、元の再生を停止します。サーバーの音楽、お気に入り、ローカルキャッシュは削除しません。同じ資格情報名を他のプロファイルが利用していなければ、保存した資格情報も削除します。

## メモリとライブラリの性能

ディスクキャッシュとデコード後の画像メモリは別に管理します。カバーとアーティスト写真の LRU テクスチャ予算は可視カバー数に応じて 40–72 MiB に変化し、200% 表示の 4K 画面にも対応します。ギャラリー画像の予算は 16 MiB です。次の可視判定が始まる前に、保留中のアップロードは前フレームで見えていたテクスチャを保護します。追い出す際はネイティブのテクスチャハンドルを解放し、再表示時にディスクキャッシュから読み込みます。画像を要求するのは見えているギャラリー／推薦カードだけです。同時に保持する画像ダウンロード、デコード、または待機中のデコード結果は最大二つで、デコードとリサイズは UI スレッド外で実行します。カバーと写真は縦横比を保って 512 px 以内、ギャラリーは 2048 px 以内に収めます。従来のカバーの陰影は維持し、アーティスト写真では使わない暗いコピーを作りません。この予算は画像テクスチャのデータだけを対象とし、プロセス全体、描画ドライバー、フォント、デコード時の一時メモリを含みません。

既存のローカルメディアキャッシュのテクスチャ予算をネットワークなしで調べるには、リポジトリのルートから `cargo run --locked --manifest-path desktop/Cargo.toml --example texture_memory_probe -- <cache-directory>` を実行します。実際の画像サイズからデコード済み RGBA データ量を見積もり、本番の LRU 方針を模擬するレポートです。プロセスのワーキングセットを測定するものではありません。

アルバム一覧は行を仮想化します。ビューポート内と上下各一行だけカードウィジェットを作り、同じ高さの余白で全体のスクロール範囲を維持します。フィルターまたはライブラリが変わるまで、絞り込みと並べ替えは共通の索引リストを再利用します。年代、アーティスト、ジャンルの選択肢はライブラリデータが変わった時だけ再構築します。カードの操作 ID はアルバムの識別子に結び付くため、行が表示領域に入ってもホバーやクリックの状態は安定します。標準の滑らかなホイール入力、カードのアニメーション時間、右端のスクロールバーの外観は維持します。

アーティスト画面はアルバム数、ジャンル候補、検索用データをフレーム間で再利用します。アーティスト情報の更新やサービスプロファイルの変更でそのスナップショットを無効にし、アルバム数やアーティスト数が同じままの更新にも対応します。ASCII の大文字小文字だけが違うジャンル名は一つの選択肢にまとめ、最も頻度の高い表記を表示します。保持するのは現在の絞り込み結果だけで、新しい検索を入力しても検索履歴キャッシュは増えません。

曲のアーティスト表記がアルバムの順序付きクレジットと完全に同じ場合、曲一覧では重複するアーティスト行を省きます。異なるクレジットの曲には個別のアーティストリンクを残します。全曲が同じクレジットならコンパクトな行を使い、一曲でも二行目が必要なら全行を同じ高い行高に揃えます。ギャラリーと類似アルバムの横並びリストでは、スクロールバーが使用可能な横幅全体に広がります。

ディスクキャッシュのヒットは LRU のアクセス時刻をメモリ内で更新し、次のキャッシュ変更と一緒に保存します。画像ごとの索引全体の書き直しは行いません。失敗した画像は 30 秒待ってから再試行し、見つからない画像への連続要求を避けます。リポジトリのルートから `cargo run --release --locked --manifest-path desktop/Cargo.toml --example scroll_layout_probe` を実行すると、全件グリッドと仮想化した egui レイアウトを画面なしで比較できます。この合成 CPU ベンチマークは可視カードとスクロール高さの一致を確認しますが、アプリの FPS、GPU 描画、画像デコード、ホイール入力遅延は測りません。

## 再生

プレーヤーは Web の配置に合わせ、コンパクトバーの一行に画像、曲情報、再生操作、シークバー、音量を並べます。画像を選ぶと「再生中」が開き、ぼかしたカバー背景、中央の二列構成、再生時のオレンジ色の操作ボタンを表示します。曲名からアルバム、アーティスト名からアーティスト画面を開き、Escape で「再生中」を閉じます。どちらのプレーヤー表示でも Space で再生／一時停止を切り替えられます。

二つの表示はシャッフル、リピートなし／全曲／一曲、ミュートを共有します。シャッフルはキューの各曲を一度ずつ再生してから停止または繰り返し、「前へ」はその順序を戻ります。シークはドラッグ中に時刻をプレビューし、離した時点で確定します。フォーカスのあるシークバーは矢印キー（五秒、Shift 併用で三十秒）と Home/End に対応します。音量も矢印キーで操作でき、ミュート解除時は直前の音量に戻します。

音声ファイルには Rodio のファイル情報を受け取るデコーダーコンストラクターを使い、ファイル全長とシーク可能性を渡します。これによりシークテーブルのない FLAC でも位置を移動できます。再生位置はオーディオ出力から直接取得し、シーク失敗時は短い通知を出します。一時的な位置上書きで失敗を隠しません。[シーク回帰テスト素材](tests/fixtures/README.ja.md)はシークテーブルのない生成音声で、前後へのシーク後のサンプルを順次デコードした結果と比較します。実際の音声出力と完全なローカルファイルで追加確認するには、ルートから `cargo run --locked --manifest-path desktop/Cargo.toml --example seek_backend_probe -- <audio-file> [<audio-file> ...]` を実行します。

## ビルドとテスト

リポジトリのルートから、最適化した Windows クライアントをビルドして実行します。

```powershell
cargo run --release --locked --manifest-path desktop/Cargo.toml
```

クライアント変更を公開する前に、ルートから `cargo test --locked --manifest-path desktop/Cargo.toml` を実行してください。ローカル HTTP ダウンロードの中断、曲の切り替え、キャッシュ消去と追い出し、アーティストキャッシュの無効化、曲行の配置を検証します。二つの合成性能ベンチマークは通常のテストから除外してあります。アーティスト集計や追い出しのコストを比べる時は `cargo test --release --locked --manifest-path desktop/Cargo.toml -- --ignored --nocapture` を実行します。その時間はアルゴリズムの測定であり、アプリの FPS やプロセスメモリの測定ではありません。

リリース設定は実行ファイルの小ささを優先します。同梱フォントはリリース exe 内で圧縮し、起動時に展開するため、対応言語と音楽情報の書体を維持できます。Debug 実行ファイルは開発用の未最適化コードを含むので大きくなります。Release 実行ファイルは Windows GUI サブシステムを使用し、端末ウィンドウを開きません。

## 更新

任意の更新元 URL は Windows クライアントの配布者が提供します。配布チャンネルがなければ空欄にしてください。Mihonban のサービス URL とは独立し、サーバーは更新しません。「更新を確認」はバージョン情報を読み、「ダウンロードと検証」は手動置換用の新しい exe を準備します。無断でインストールはしません。

更新元はクライアント配布チャンネルが公開する小さな JSON 文書を指します。例：

```json
{
  "latest": "0.2.0",
  "download_url": "https://github.com/hanfdev/mihonban/releases/download/desktop-v0.2.0/mihonban_desktop.exe",
  "sha256": "...",
  "notes": "..."
}
```

サーバー要件は[ネイティブ API 互換性契約](API_COMPATIBILITY.ja.md)、サーバーの導入と他のクライアントは[プロジェクトガイド](../README.ja.md)を参照してください。
