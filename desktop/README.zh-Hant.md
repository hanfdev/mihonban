# Mihonban 原生 Windows 用戶端

[English](README.md) · [简体中文](README.zh.md) · [繁體中文](README.zh-Hant.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Français](README.fr.md) · [Español](README.es.md)

此目錄包含 Rust 原生桌面用戶端。它使用 `egui` 繪製介面，透過 `reqwest` 直接存取 Mihonban HTTP API，並以 `rodio` / Symphonia 在本機解碼支援的音訊格式。它不嵌入瀏覽器，也不載入 Mihonban 網頁應用程式。

用戶端支援多個 Mihonban 服務設定檔。服務位址可在設定中修改，密碼儲存於 Windows 認證管理員，可選的用戶端更新資訊清單與 Mihonban 伺服器發行獨立。帶標籤的建置發佈於 [GitHub Releases](https://github.com/hanfdev/mihonban/releases)（`desktop-v*` 標籤），每個版本均附帶可攜式 exe 和 SHA-256 校驗檔。

## 介面、設定與快取

用戶端啟動時在所在顯示器上最大化，並遵循 Windows 顯示縮放及工作列工作區。啟動視埠刻意不指定固定內部尺寸：eframe 0.29 會在建立最大化視窗後套用該尺寸，可能導致視窗縮小卻仍保留最大化狀態。

連線卡片依內容調整大小，始終置中於導覽列下方；翻譯文字或錯誤提示改變高度時亦然。精簡的伺服器標示顯示主機、連接埠及部署路徑，工具提示保留完整位址。連線失敗時可直接選擇重試或設定。

介面延續 Mihonban 的深色檔案館／黑膠風格：固定頁首、置中搜尋、封面牆、音盤主視覺與曲目清單，以及常駐的原生播放器。封面和音訊使用依服務設定檔隔離的持久快取。設定提供快取目錄、1–200 GB 容量上限、目前用量、清除快取及檔案總管捷徑。快取採用不可分割寫入和最近最少使用淘汰策略；大於設定上限的檔案只播放一次，不予保留。

切換歌曲會取消被替換的音訊下載。停止播放和取消預先載入也會釋放相應連線及未完成檔案，即使磁碟快取已關閉也是如此。清除已啟用的快取會取消進行中的下載，防止稍後重新寫入。已完成檔案仍可用於播放；未完成下載在工作結束或取消時清理。若其他處理程序暫時鎖定未完成檔案，後續啟動會刪除遺留超過十分鐘的快取片段。

藝人網格和詳細頁面的頭像均置中裁切並保持長寬比，與 Web 用戶端針對橫向、直向照片的 `object-fit: cover` 行為一致。

在 Windows 上，最小化預設將用戶端隱藏到原生系統匣圖示，播放和佇列推進繼續在背景執行。按兩下 Mihonban 原始圖示，或在右鍵選單選擇「顯示主視窗」，即可還原視窗。選單另提供播放／暫停和結束。設定 → 視窗行為分別儲存最小化及關閉時隱藏到系統匣的選項。關閉視窗預設仍結束程式，系統匣的結束命令始終結束。系統匣初始化失敗時仍可正常使用視窗。

預設快取位於 Windows 本機應用程式資料目錄。更改目錄或容量僅影響原生用戶端，不會更改 Mihonban 伺服器及其儲存空間。

設定依 Windows 使用者儲存於 `%APPDATA%\Mihonban\Mihonban\config\config.json`。同一帳戶下的所有用戶端副本，無論 exe 位於何處，都讀取相同的服務設定檔、視窗偏好及快取設定。密碼以設定檔名稱為索引，另存於 Windows 認證管理員。沒有已儲存設定檔的電腦使用內建的本機預留位址啟動。

設定頁面與曲庫使用相同的暖黑底色、襯線標題、細邊框及橙色操作按鈕。置中的頁面在寬視窗下顯示服務表單及視窗／更新側欄，在窄視窗下改為垂直堆疊的全寬卡片。原生輸入欄位、鍵盤可操作的開關、可換行操作區和本機儲存用量指示均支援七種介面語言。快取的開關、目錄及容量變更需要儲存快取設定後生效；視窗隱藏到系統匣的選項繼續自動儲存。

可在服務卡片中刪除伺服器設定檔。確認對話方塊明確顯示設定檔名稱和位址，預設選擇取消，並要求再次確認。至少保留一個設定檔。刪除目前選取的設定檔會切換至其他已儲存設定檔並停止原先的播放，不會刪除伺服器上的音樂、精選或本機快取媒體。已儲存認證隨之刪除，但仍有其他設定檔使用同一認證名稱時除外。

## 記憶體與曲庫效能

磁碟快取與解碼後的影像記憶體分別管理。封面和藝人照片採用隨可見封面數量變化的 LRU 紋理預算（40–72 MiB，涵蓋 200% 縮放的 4K 顯示器），內頁圖預算為 16 MiB。新一輪可見性判斷開始前，待上傳紋理會保留上一幀仍可見的紋理。淘汰會釋放原生紋理控制代碼，再次查看時從磁碟快取重新載入。僅可見的內頁／推薦卡片請求圖片；同時最多保留兩個圖片下載、解碼工作或排隊等待的解碼結果，解碼和縮放均在 UI 執行緒之外執行。封面和照片保持長寬比並限制在 512 px 內，內頁圖限制在 2048 px 內。封面原有的明暗處理不變，藝人照片不再配置未使用的暗化副本。上述預算僅包含影像紋理資料，不涵蓋整個處理程序、顯示驅動程式、字型或解碼時的暫存配置。

從儲存庫根目錄執行 `cargo run --locked --manifest-path desktop/Cargo.toml --example texture_memory_probe -- <cache-directory>`，可在不存取網路的情況下檢查既有本機媒體快取的紋理預算。報告依實際影像尺寸估算解碼後的 RGBA 資料量，並模擬正式環境的 LRU 策略；它不是處理程序工作集測量。

音盤牆對列進行虛擬化：只有視埠內及上下各一列的卡片會建立控制項，等高留白保留完整捲動範圍。篩選條件或曲庫未變動時，篩選和排序重複使用共用索引清單；年代、藝人和曲風選項僅在曲庫資料變更時重建。卡片互動 ID 跟隨音盤身分，因此列進入視埠時懸停及點選狀態保持穩定。原生平滑滾輪輸入、卡片動畫時序和右側捲軸樣式均保留。

藝人頁面在影格之間重複使用音盤總數、曲風選項及搜尋資料。藝人資料重新整理或服務設定檔切換會使該快照失效，即使更新前後音盤或藝人數量不變。僅 ASCII 字母大小寫不同的曲風合併為一個篩選選項，顯示出現次數最多的拼寫。只保留目前篩選結果，輸入新搜尋不會累積搜尋歷程快取。

曲目的藝人署名與音盤的有序署名完全相同時，曲目清單省略重複藝人列；署名不同的曲目仍保留各藝人連結。整張音盤沒有差異署名時使用精簡列；只要一首需要第二行，所有曲目都使用相同的較高列高。內頁圖與相似音盤橫向清單的捲軸涵蓋整列可用寬度。

磁碟快取命中時僅在記憶體更新 LRU 存取時間，並在下次快取變更時儲存，避免每張圖片都重寫整份索引。圖片失敗後等待 30 秒再重試，避免持續請求缺失封面。從儲存庫根目錄執行 `cargo run --release --locked --manifest-path desktop/Cargo.toml --example scroll_layout_probe`，可在無介面環境比較完整網格與虛擬化 egui 版面。此合成 CPU 基準檢查可見卡片與捲動高度是否等價，不測量應用程式 FPS、GPU 繪製、影像解碼或滾輪輸入延遲。

## 播放

播放器沿用 Web 版面：精簡列將封面、曲目資訊、播放控制、進度及音量排在同一行。點選封面開啟「正在播放」，使用模糊封面背景、置中的雙欄構圖，以及播放時的橙色控制按鈕。點選曲名進入音盤，點選藝人名稱進入藝人頁，Escape 收起「正在播放」。兩種播放器檢視均可用空白鍵切換播放／暫停。

兩種檢視共用隨機、關閉循環／全部循環／單曲循環及靜音控制。隨機播放會遍歷佇列中的每首曲目一次，然後停止或循環；上一首沿相同順序回溯。拖曳進度列時預覽時間，放開時提交定位。進度列取得焦點後可使用方向鍵（每次五秒，按住 Shift 時三十秒）及 Home/End；音量支援方向鍵，取消靜音時還原先前可聽見的音量。

音訊檔案使用 Rodio 能辨識檔案資訊的解碼器建構函式，使其取得完整檔案長度及可定位屬性，因此沒有定位表的 FLAC 也可定位播放。播放位置直接來自音訊輸出端；定位失敗會顯示簡短提示，不使用暫時覆寫位置來隱藏失敗。[定位回歸測試素材](tests/fixtures/README.zh-Hant.md)包含沒有定位表的生成音訊，測試將前後定位後的取樣與循序解碼比較。如需使用真實音訊輸出及完整本機檔案進行額外檢查，可從儲存庫根目錄執行 `cargo run --locked --manifest-path desktop/Cargo.toml --example seek_backend_probe -- <audio-file> [<audio-file> ...]`。

## 建置與測試

從儲存庫根目錄建置並執行最佳化後的 Windows 用戶端：

```powershell
cargo run --release --locked --manifest-path desktop/Cargo.toml
```

發佈用戶端變更前，在儲存庫根目錄執行 `cargo test --locked --manifest-path desktop/Cargo.toml`。測試涵蓋本機 HTTP 下載中斷、切歌、快取清除與淘汰、藝人快取失效，以及曲目列版面回歸。兩個合成效能基準預設不參加一般測試；比較藝人彙總或淘汰成本時，執行 `cargo test --release --locked --manifest-path desktop/Cargo.toml -- --ignored --nocapture`。其計時反映演算法成本，不是應用程式 FPS 或處理程序記憶體測量。

Release 設定優先縮小可執行檔。內建字型壓縮進發行版 exe，在啟動時解壓縮，保留各介面語言及音樂資料的字型效果。Debug 可執行檔因包含未最佳化的開發程式碼而較大。Release 使用 Windows GUI 子系統，開啟時不會出現終端機視窗。

## 更新

可選的更新來源 URL 由 Windows 用戶端發佈者提供。沒有發佈管道時請留空；它與 Mihonban 服務位址獨立，不會更新伺服器。「檢查更新」讀取版本資料，「下載並校驗」準備新 exe，供手動替換，不會無提示安裝。

更新來源指向用戶端發佈管道託管的小型 JSON 文件，例如：

```json
{
  "latest": "0.2.0",
  "download_url": "https://github.com/hanfdev/mihonban/releases/download/desktop-v0.2.0/mihonban_desktop.exe",
  "sha256": "...",
  "notes": "..."
}
```

伺服器要求見[原生 API 相容性約定](API_COMPATIBILITY.zh-Hant.md)，伺服器安裝與其他用戶端見[專案指南](../README.zh-Hant.md)。
