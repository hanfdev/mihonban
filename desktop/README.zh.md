# Mihonban 原生 Windows 客户端

[English](README.md) · [简体中文](README.zh.md) · [繁體中文](README.zh-Hant.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Français](README.fr.md) · [Español](README.es.md)

此目录包含 Rust 原生桌面客户端。它使用 `egui` 绘制界面，通过 `reqwest` 直接访问 Mihonban HTTP API，并使用 `rodio` / Symphonia 在本地解码支持的音频格式。它不嵌入浏览器，也不加载 Mihonban 网页应用。

客户端支持多个 Mihonban 服务配置。服务地址可在设置中修改，口令保存在 Windows 凭据管理器中，可选的客户端更新清单与 Mihonban 服务器发布独立。带标签的构建发布于 [GitHub Releases](https://github.com/hanfdev/mihonban/releases)（`desktop-v*` 标签），每个版本均附带便携 exe 和 SHA-256 校验文件。

## 界面、设置与缓存

客户端启动时在所在显示器上最大化，并遵循 Windows 显示缩放和任务栏工作区。启动视口刻意不指定固定内部尺寸：eframe 0.29 会在创建最大化窗口后应用该尺寸，可能导致窗口缩小却仍保留最大化状态。

连接卡片根据内容调整大小，始终居中显示于导航栏下方；翻译文本或错误提示改变高度时也如此。紧凑的服务器标识显示主机、端口和部署路径，提示框保留完整地址。连接失败时可直接选择重试或设置。

界面延续 Mihonban 的深色档案馆／黑胶风格：固定页头、居中搜索、封面墙、音盘主视觉和曲目列表，以及常驻的原生播放器。封面和音频使用按服务配置隔离的持久缓存。设置提供缓存目录、1–200 GB 容量上限、当前用量、清空缓存和资源管理器快捷入口。缓存采用原子写入和最近最少使用淘汰策略；大于设定上限的文件只播放一次，不予保留。

切换歌曲会取消被替换的音频下载。停止播放和取消预加载也会释放对应连接及未完成文件，即使磁盘缓存已关闭也是如此。清空已启用的缓存会取消正在进行的下载，防止随后重新写入。已完成文件仍可用于播放；未完成下载在任务结束或取消时清理。若其他进程暂时锁定了未完成文件，后续启动会删除遗留超过十分钟的缓存片段。

艺人网格和详情页的头像均居中裁切并保持宽高比，与 Web 客户端针对横向、纵向照片的 `object-fit: cover` 行为一致。

在 Windows 上，最小化默认将客户端隐藏到原生系统托盘图标，播放和队列推进继续在后台运行。双击 Mihonban 原始图标，或在右键菜单选择“显示主窗口”，即可恢复窗口。菜单还提供播放／暂停和退出。设置 → 窗口行为分别保存最小化和关闭时隐藏到托盘的选项。关闭窗口默认仍退出程序，托盘的退出命令始终退出。托盘初始化失败时仍可正常使用窗口。

默认缓存位于 Windows 本地应用数据目录。更改目录或容量仅影响原生客户端，不会更改 Mihonban 服务器及其存储。

设置按 Windows 用户保存在 `%APPDATA%\Mihonban\Mihonban\config\config.json`。同一账户下的所有客户端副本，无论 exe 所在目录为何，都会读取相同的服务配置、窗口偏好和缓存设置。口令以配置名称为键，另存于 Windows 凭据管理器。没有已保存配置的电脑使用内置的本地占位地址启动。

设置页面与曲库使用相同的暖黑底色、衬线标题、细边框和橙色操作按钮。居中的页面在宽窗口下显示服务表单及窗口／更新侧栏，在窄窗口下改为纵向堆叠的全宽卡片。原生输入框、键盘可操作的开关、可换行操作区和本地存储用量指示均支持七种界面语言。缓存的开关、目录和容量变更需要保存缓存设置后生效；窗口隐藏到托盘的选项继续自动保存。

可在服务卡片中删除服务器配置。确认对话框明确显示配置名称和地址，默认选择取消，并要求再次确认。至少保留一个配置。删除当前选中的配置会切换到其他已保存配置并停止原先的播放，不会删除服务器上的音乐、精选或本地缓存媒体。已保存凭据随之删除，但仍有其他配置使用同一凭据名称时除外。

## 内存与曲库性能

磁盘缓存与解码后的图像内存分别管理。封面和艺人照片采用随可见封面数量变化的 LRU 纹理预算（40–72 MiB，涵盖 200% 缩放的 4K 显示器），内页图预算为 16 MiB。新一轮可见性判断开始前，待上传纹理会尊重上一帧仍可见的纹理。淘汰会释放原生纹理句柄，再次查看时从磁盘缓存重新载入。仅可见的内页／推荐卡片请求图片；同时最多保留两个图片下载、解码任务或排队等待的解码结果，解码和缩放均在 UI 线程之外执行。封面和照片保持宽高比并限制在 512 px 内，内页图限制在 2048 px 内。封面原有的明暗处理不变，艺人照片不再分配未使用的暗化副本。上述预算仅包含图像纹理数据，不涵盖整个进程、图形驱动、字体或解码时的临时分配。

从仓库根目录运行 `cargo run --locked --manifest-path desktop/Cargo.toml --example texture_memory_probe -- <cache-directory>`，可在不访问网络的情况下检查已有本地媒体缓存的纹理预算。报告依据实际图像尺寸估算解码后的 RGBA 数据量，并模拟生产环境的 LRU 策略；它不是进程工作集测量。

音盘墙对行进行虚拟化：只有视口内及上下各一行的卡片会创建控件，等高占位保留完整滚动范围。筛选条件或曲库未改变时，筛选和排序复用共享索引列表；年代、艺人和风格选项仅在曲库数据变化时重建。卡片交互 ID 跟随音盘身份，因此行进入视口时悬停和点击状态保持稳定。原生平滑滚轮输入、卡片动画时序和右侧滚动条样式均保留。

艺人页面在帧之间复用音盘总数、风格选项和搜索数据。艺人资料刷新或服务配置切换会使该快照失效，即使更新前后音盘或艺人数量不变。仅 ASCII 字母大小写不同的风格合并为一个筛选选项，显示出现次数最多的拼写。只保留当前筛选结果，输入新搜索不会累积搜索历史缓存。

曲目的艺人署名与音盘的有序署名完全相同时，曲目列表省略重复艺人行；署名不同的曲目仍保留各艺人链接。整张音盘没有差异署名时使用紧凑行；只要一首需要第二行，所有曲目都使用相同的较高行高。内页图和相似音盘横向列表的滚动条覆盖整行可用宽度。

磁盘缓存命中时仅在内存更新 LRU 访问时间，并在下次缓存变更时保存，避免每张图片都重写整个索引。图片失败后等待 30 秒再重试，避免持续请求缺失封面。从仓库根目录运行 `cargo run --release --locked --manifest-path desktop/Cargo.toml --example scroll_layout_probe`，可在无界面环境比较完整网格与虚拟化 egui 布局。该合成 CPU 基准检查可见卡片与滚动高度是否等价，不测量应用 FPS、GPU 渲染、图像解码或滚轮输入延迟。

## 播放

播放器沿用 Web 布局：紧凑栏将封面、曲目信息、播放控制、进度和音量排在同一行。点击封面打开“正在播放”，使用模糊封面背景、居中的双栏构图，以及播放时的橙色控制按钮。点击曲名进入音盘，点击艺人名称进入艺人页，Escape 收起“正在播放”。两种播放器视图均可用空格切换播放／暂停。

两种视图共用随机、关闭循环／全部循环／单曲循环及静音控制。随机播放会遍历队列中的每首曲目一次，然后停止或循环；上一首沿相同顺序回溯。拖动进度条时预览时间，松开时提交跳转。进度条获得焦点后可使用方向键（每次五秒，按住 Shift 时三十秒）及 Home/End；音量支持方向键，取消静音时恢复先前可听见的音量。

音频文件使用 Rodio 能识别文件信息的解码器构造函数，使其获得完整文件长度与可跳转属性，因此没有跳转表的 FLAC 也可定位播放。播放位置直接来自音频输出端；定位失败会显示简短提示，不使用临时覆盖位置来隐藏失败。[定位回归测试素材](tests/fixtures/README.zh.md)包含没有跳转表的生成音频，测试将前后定位后的采样与顺序解码比较。如需使用真实音频输出和完整本地文件进行额外检查，可从仓库根目录运行 `cargo run --locked --manifest-path desktop/Cargo.toml --example seek_backend_probe -- <audio-file> [<audio-file> ...]`。

## 构建与测试

从仓库根目录构建并运行优化后的 Windows 客户端：

```powershell
cargo run --release --locked --manifest-path desktop/Cargo.toml
```

发布客户端变更前，在仓库根目录运行 `cargo test --locked --manifest-path desktop/Cargo.toml`。测试覆盖本地 HTTP 下载中断、切歌、缓存清空与淘汰、艺人缓存失效以及曲目行布局回归。两个合成性能基准默认不参加常规测试；比较艺人汇总或淘汰成本时，运行 `cargo test --release --locked --manifest-path desktop/Cargo.toml -- --ignored --nocapture`。其计时反映算法成本，不是应用 FPS 或进程内存测量。

Release 配置优先缩小可执行文件。内置字体压缩进发布版 exe，在启动时解压，保留各界面语言和音乐资料的字体效果。Debug 可执行文件因包含未优化的开发代码而较大。Release 使用 Windows GUI 子系统，打开时不会出现终端窗口。

## 更新

可选的更新源 URL 由 Windows 客户端发布者提供。没有发布渠道时请留空；它与 Mihonban 服务地址独立，不会更新服务器。“检查更新”读取版本资料，“下载并校验”准备新 exe，供手动替换，不会静默安装。

更新源指向客户端发布渠道托管的小型 JSON 文档，例如：

```json
{
  "latest": "0.2.0",
  "download_url": "https://github.com/hanfdev/mihonban/releases/download/desktop-v0.2.0/mihonban_desktop.exe",
  "sha256": "...",
  "notes": "..."
}
```

服务器要求见[原生 API 兼容性约定](API_COMPATIBILITY.zh.md)，服务器安装和其他客户端见[项目指南](../README.zh.md)。
