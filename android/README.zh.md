## 安装与连接

当前预览版本为 0.1.10，可本地构建，或从成功的 [Android 工作流](https://github.com/hanfdev/mihonban/actions/workflows/android.yml)下载 debug APK。release APK 需要使用自己的密钥签名。填写服务器根地址，例如 `https://music.example.com` 或 `http://192.168.1.20:8788`，并输入听众或管理员口令；仅在服务器允许访客访问时留空。Android 模拟器可通过 `http://10.0.2.2:8788` 访问宿主电脑的开发服务器。手机访问电脑时使用电脑的局域网 IP；手机的 `localhost` 指向手机自身。

远程服务器建议使用 HTTPS。现有 Node/Wrangler 开发模式支持本地 HTTP，但服务器必须设置 `DEV_INSECURE_COOKIE=1` 才能使用 HTTP 会话 Cookie。应用不会跳过 TLS 证书验证。

## 原生功能

- 专辑网格、歌曲列表、风格筛选、年份／标题／艺人／评分／最近加入排序、全库搜索、多艺人署名与艺人作品页。
- 专辑详情、评分、简介、相关专辑、内页翻阅与双指缩放、Android 分享面板，以及共享的专辑和歌曲精选。
- 迷你播放器、完整播放器、进度拖动、随机、循环、可编辑队列、下一首播放、睡眠定时、音频焦点与耳机断开处理。
- Media3 前台播放服务，支持通知、耳机和锁屏控制。界面进入后台后继续播放；进程重启后恢复处于暂停状态的队列。
- WorkManager 将下载保存到应用私有存储，提供进度、暂停／重试／删除、校验后的字节范围续传、持久化资料和专辑封面、离线播放与缓存曲库浏览。
- 管理员可编辑专辑／歌曲／艺人、调整可见性、确认后删除、导入 Discogs 元数据和内页、重排图片、通过 Android 文件选择器上传音频、扫描并登记服务器文件夹。
- 服务器管理包括访客访问与模块设置、命名存储配置／测试／写入目标、R2 配置和测试、来源收件箱与扫描，以及听众／管理员口令修改。
- 沿用 Web 的黑褐底色、暖米白文字、朱红强调色和衬线标题；触控目标、底部导航、滚动位置恢复、系统返回、旋转和安全区使用原生 Compose 行为。

曲库直接进入专辑或歌曲。向上滚动收起顶部栏，向下滚动恢复。网格密度可切换，风格和排序放在可关闭的底部面板。搜索提供现有风格、最近加入专辑和结果分类。专辑详情将封面与资料并排，次要操作集中在菜单中。标签页状态按服务器和访问身份分别保存。最近加入按专辑首次入库时间排序，修改评分或其他资料不会让旧专辑排到最前。

0.1.3 将内嵌简介展开替换为独立阅读页。专辑页保留三行纯文本摘要；阅读页标题和关闭按钮固定，支持回到顶部，关闭时恢复专辑位置，再次打开时保留阅读进度。CommonMark 与 GFM 表格／删除线原生渲染，支持文字选择、嵌套列表、引用、链接、代码、分隔线和独立图片；宽表格与代码横向滚动。原始 HTML 作为文本显示。配色和字体沿用 Web，不使用 WebView。

0.1.4 为简介图片增加加载反馈、可读替代文字和“重新加载图片”按钮，避免失败时只有空白。重试只重新加载该图片，阅读页保持打开。不可用地址会显示说明，不提供无效重试。

0.1.5 修复只有一个长段落或引用块时的“回到顶部”：现在计算 Markdown 块内部滚动，并在回到开头时隐藏按钮。标题字体在 Activity 重建之间共享，避免重复分配内置字体缓冲区。

0.1.6 在 WorkManager 任务停止时取消活动下载请求，包括服务器尚未返回响应头或在响应体中卡住的情况。暂停或删除下载无需等待网络超时。封面下载采用相同取消处理。手动重试从头开始，自动重试可继续经过校验的部分数据。

0.1.7 让与文字或说明共处一段的简介图片正常显示。文字和图片按原文顺序排列，保持可读间距，嵌套引用也适用；周围文字保留 Markdown 格式，图片保留加载反馈和重试操作。

0.1.8 将竖屏播放控制上移并拉近封面与标题。在底部增加当前歌曲下载、分享、队列快捷栏。下载提供进度和暂停／重试，已完成下载保持完整。分享通过 Android 面板发送歌名、艺人和 Web 专辑链接。横屏将快捷栏放在封面下方，为歌曲资料留出空间。完整播放器资料区仍只显示标题和艺人。

0.1.9 默认按加权评分排列专辑，使用与 Web 相同的置信度调整和同分排序规则。点击专辑的主风格或次风格会打开按此规则排序的匹配专辑，返回时回到原专辑。收起顶部栏后完整裁去标题和图标，保留系统状态栏区域。

0.1.10 修复顶部栏几乎收起时残留的标题／图标碎片：完整高度的栏整体滑出，而非把控件居中挤在缩小的窄条内；使用实际测量的收起距离，并在末段淡出。显示缩放变化后仍保持收起位置。状态栏留白位于滑动行之外。

“我的 → 播放设置”提供下一首预加载：仅 Wi-Fi（默认）、始终开启和关闭。仅 Wi-Fi 模式在默认网络切换到移动数据时取消预加载，回到 Wi-Fi 后恢复。随机播放时跟随实际下一首，等待当前歌曲缓冲后开始，跳过已下载歌曲，暂停时停止。最多将下一首的前 16 MiB 放入现有的服务器／身份隔离音乐缓存，受其容量上限约束，播放时复用这些字节。这是设备偏好，不需要管理员权限。

320–599 dp 的手机明确切换两列／三列，更窄窗口和平板也使用不同列数。网格按钮为无数字、无强调色的中性图标，读屏仍会播报当前列数。偏好跨重启保存，曲库、精选和风格页共用。曲库支持下拉刷新。队列打开时定位当前歌曲，返回键回到播放器，清空队列需确认。

0.1.2 将播放控制保持在可用安全区内，封面随剩余空间缩放。资料区仅显示歌名和艺人，点击标题打开专辑；缓冲时保留可操作的播放／暂停图标。歌曲列表的随机按钮只切换选择状态，按“播放全部”后才启动或改变播放；专辑详情的随机按钮直接播放该专辑。

“我的 → 缓存设置”显示音乐／图片磁盘占用，提供 128 MB～2 GB 的音乐缓存上限及自动音乐／图片缓存清理。降低上限会立即淘汰较旧音乐数据；图片独立限制为 64 MB。主动下载、已存曲库和登录状态保留，活动播放可能生成新缓存。流缓存键包含服务器和访问身份。

精选是服务器共享的人工选集：与 Web 一样，听众和访客只读，仅管理员可修改。服务器地址、曲库快照、图片和下载按服务器及访问身份隔离。会话 Cookie 使用 Android Keystore AES-GCM 加密保存，不保存口令。应用数据不参加 Android 备份。

## 构建与测试

需要 JDK 17、Android SDK platform 35 和 Build Tools 35.0.0。可用 Android Studio 打开本目录，或在仓库根目录运行：

```powershell
android\gradlew.bat -p android testDebugUnitTest lintDebug assembleDebug assembleRelease
android\gradlew.bat -p android connectedDebugAndroidTest
```

macOS/Linux：

```sh
sh android/gradlew -p android testDebugUnitTest lintDebug assembleDebug assembleRelease
sh android/gradlew -p android connectedDebugAndroidTest
```

通过 `ANDROID_HOME` 或忽略的 `android/local.properties` 中的 `sdk.dir` 指定 SDK。包装脚本固定 Gradle 8.9。测试无需生产服务器、凭据或音频。JVM 测试覆盖 JSON 兼容、URL／Cookie 隔离、重定向安全和下载范围验证；设备测试通过内嵌 HTTP 测试服务和合成 PCM 音频验证原生导航、播放、拖动、队列、下载及离线播放。

输出：

- 可安装开发 APK：`app/build/outputs/apk/debug/app-debug.apk`。
- 未签名发布 APK：`app/build/outputs/apk/release/app-release-unsigned.apk`。分发前使用自己的发布密钥签名，并保留该密钥用于后续更新。
- JVM 与 lint 报告：`app/build/reports/`。

Android GitHub Actions 工作流构建两种变体并执行 JVM／lint 检查，另有 API 35 模拟器任务；不会自动发布版本或使用生产密钥签名。

验证命令、历史结果和设备覆盖范围见[验证记录](VERIFICATION.zh.md)。代表性文档截图保存在 `docs/images/`；APK、完整截图集和构建报告仍是生成产物，不随源码提交。CI 产物需要访问对应工作流，并按 GitHub 保留设置过期。

## 当前边界

格式支持取决于 Media3 和设备解码器，包括常见 MP3、FLAC、AAC、WAV、Vorbis 和 Opus；未内置 DSD/APE 等专用编解码器。手机上传可跨旋转继续，但属于前台编辑操作，登记完成前须保持应用打开，尚不是持久后台上传队列。若登记前取消，可能需在存储服务中清理已上传的部分文件。

主听歌界面随设备语言提供中英文，管理界面目前为简体中文。浏览器辅助 RYM 更新及保存的 HTML 导入、完整配置备份／恢复、批量存储迁移和存储 OAuth 设置仍在 Web 中完成。本客户端连接现有服务器，不托管服务器。

项目使用仓库的 AGPL-3.0-only 许可证；第三方依赖保留各自许可证。内置 Shippori Mincho 与 GenRyu Mincho 和 Web 使用相同字体，SIL Open Font License 文本位于 `app/src/main/assets/licenses/`。
