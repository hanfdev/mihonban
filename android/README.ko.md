# Android용 Mihonban

[English](README.md) · [简体中文](README.zh.md) · [繁體中文](README.zh-Hant.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Français](README.fr.md) · [Español](README.es.md)

기존 Mihonban 서버에 연결하는 Kotlin / Jetpack Compose 네이티브 클라이언트입니다. WebView를 사용하지 않으며 Android 8.0(API 26) 이상이 필요합니다.

## 연결

현재 미리 보기 버전 0.1.10을 직접 빌드하거나 성공한 [Android 워크플로 실행](https://github.com/hanfdev/mihonban/actions/workflows/android.yml)에서 debug APK를 받으세요. release APK에는 자신의 서명 키가 필요합니다. 서버 루트 주소(예: `https://music.example.com`, `http://192.168.1.20:8788`)와 청취자 또는 관리자 암호를 입력하세요. 서버가 게스트 접근을 허용할 때만 암호를 비울 수 있습니다. Android 에뮬레이터는 `http://10.0.2.2:8788`로 호스트 개발 서버에 접근할 수 있습니다.

원격 서버에는 HTTPS를 권장합니다. 기존 Node/Wrangler 개발 모드는 로컬 HTTP를 지원하며, HTTP 쿠키 세션을 쓰려면 서버에 `DEV_INSECURE_COOKIE=1`을 설정해야 합니다. 앱은 TLS 인증서 검증을 우회하지 않습니다.

## 네이티브 기능

- 앨범 그리드와 곡 목록, 장르 필터, 연도/제목/아티스트/평점/최근 추가 순 정렬, 전체 라이브러리 검색, 여러 아티스트 표기와 아티스트별 작품 목록.
- 앨범 상세, 평점, 설명, 관련 앨범, 내지 페이지 전환과 핀치 확대, Android 공유 시트, 공유 앨범/곡 즐겨찾기.
- 미니/전체 플레이어, 탐색, 셔플, 반복, 편집 가능한 큐, 다음에 재생, 수면 타이머, 오디오 포커스 및 헤드폰 분리 처리.
- 알림·헤드셋·잠금 화면 제어를 제공하는 Media3 포그라운드 재생 서비스. UI가 백그라운드에 있어도 재생하며, 프로세스 재시작 후 큐는 일시 정지 상태로 복원됩니다.
- WorkManager를 통한 앱 전용 저장소 다운로드, 진행률, 일시 정지/재시도/삭제, 검증된 바이트 범위 이어받기, 영구 메타데이터와 앨범 표지, 오프라인 재생 및 캐시 라이브러리 탐색.
- 관리자 기능: 앨범/곡/아티스트 편집, 표시 여부, 확인 후 삭제, Discogs 메타데이터·내지 가져오기, 이미지 순서 변경, Android 문서 선택기를 통한 음원 업로드, 서버 폴더 스캔 및 등록.
- 서버 관리: 게스트 접근과 모듈 설정, 이름 있는 저장소 설정/테스트/쓰기 대상, R2 설정/테스트, 소스 수신함과 스캔, 청취자/관리자 암호 변경.
- Web의 흑갈색 배경, 따뜻한 아이보리 글자, 주홍색 강조, 세리프 제목을 유지합니다. 터치 영역, 하단 탐색, 스크롤 복원, 시스템 뒤로 가기, 회전 및 여백은 네이티브 Compose 동작을 사용합니다.

라이브러리는 앨범 또는 곡을 바로 엽니다. 위로 스크롤하면 상단 앱 바가 접히고 아래로 스크롤하면 돌아옵니다. 그리드 밀도를 바꿀 수 있고 장르/정렬은 닫을 수 있는 하단 시트에 있습니다. 검색은 기존 장르, 최근 추가 앨범과 결과 범주를 제공합니다. 앨범 상세는 표지와 정보를 나란히 배치하고 보조 동작은 메뉴에 모읍니다. 탭 상태는 서버와 접근 역할별로 저장합니다. 최근 추가 정렬은 앨범의 최초 등록 시간을 사용하므로 평점이나 메타데이터를 수정해도 오래된 앨범이 맨 앞으로 이동하지 않습니다.

0.1.3은 설명의 인라인 펼치기를 전용 읽기 화면으로 바꿉니다. 앨범에는 일반 텍스트 세 줄 요약을 남기며 읽기 화면의 머리글과 닫기 버튼은 고정됩니다. 맨 위로 이동, 닫을 때 앨범 위치 복원, 다시 열 때 읽던 위치 보존을 지원합니다. CommonMark와 GFM 표/취소선을 네이티브로 렌더링하며 선택 가능한 텍스트, 중첩 목록, 인용, 링크, 코드, 구분선, 독립 이미지를 지원합니다. 넓은 표와 코드는 가로 스크롤됩니다. 원시 HTML은 실행되지 않는 텍스트입니다. WebView 없이 Web의 색상과 서체를 따릅니다.

0.1.4는 설명 이미지 실패를 명확하게 표시합니다. 로딩 표시, 읽을 수 있는 대체 텍스트, 이미지 재시도 버튼이 빈 공간을 대신합니다. 재시도는 해당 이미지만 다시 불러오며 읽기 화면을 유지합니다. 사용할 수 없는 주소에는 설명을 보여 주고 성공할 수 없는 재시도는 제공하지 않습니다.

0.1.5는 설명이 긴 문단이나 인용 하나일 때의 맨 위로 이동을 수정합니다. Markdown 블록 내부 스크롤도 계산하고 시작점에서는 버튼을 숨깁니다. Activity 재생성 사이에 제목 글꼴을 공유하여 내장 글꼴 버퍼의 반복 할당도 방지합니다.

0.1.6은 WorkManager 작업이 멈출 때 활성 다운로드 요청을 취소합니다. 응답 헤더 전이나 본문 전송 중 서버가 멈춘 경우도 포함됩니다. 일시 정지/삭제 시 네트워크 제한 시간을 기다리지 않습니다. 다운로드 표지 요청도 같은 취소 처리를 사용합니다. 수동 재시도는 새로 시작하고 자동 재시도는 검증된 부분 데이터를 이어받을 수 있습니다.

0.1.7은 텍스트나 캡션과 같은 문단에 있는 설명 이미지도 표시합니다. 중첩 인용 안에서도 원래 순서와 읽기 좋은 간격을 유지하고 주변 텍스트의 Markdown 형식을 보존합니다. 이미지 로딩 표시와 재시도는 유지됩니다.

0.1.8은 세로 화면의 재생 제어를 하단 가장자리에서 올리고 표지를 제목에 가깝게 둡니다. 하단 보조 행에 현재 곡 다운로드, 공유, 큐를 제공합니다. 다운로드는 진행률과 일시 정지/재시도를 지원하고 완료된 파일을 보존합니다. 공유는 곡, 아티스트, Web 앨범 링크를 Android 선택기로 보냅니다. 가로 화면에서는 보조 행을 표지 아래에 배치하여 곡 정보 공간을 확보합니다. 전체 플레이어 메타데이터는 여전히 제목과 아티스트뿐입니다.

0.1.9는 Web과 같은 신뢰도 보정 및 동점 정렬을 적용한 가중 평점을 기본 순서로 사용합니다. 앨범의 주/보조 장르를 누르면 해당 순서의 일치 앨범을 열고 뒤로 가면 원래 앨범으로 돌아옵니다. 접힌 도구 모음은 제목/아이콘을 완전히 잘라내되 시스템 상태 표시줄 영역을 유지합니다.

0.1.10은 도구 모음이 거의 접혔을 때 남는 제목/아이콘 조각을 수정합니다. 줄어드는 띠 안에 제어를 가운데 정렬하는 대신 전체 높이의 도구 모음을 바깥으로 밀고 실제 접힘 거리를 측정해 끝부분을 흐리게 합니다. 화면 배율 변경 후에도 닫힌 위치를 유지하며 상태 표시줄 여백은 이동하는 행 밖에 둡니다.

More → Playback settings에서 다음 곡 미리 읽기를 Wi-Fi만(기본), 항상, 끄기로 설정합니다. Wi-Fi만 모드는 기본 네트워크가 모바일로 바뀌면 예상 요청을 취소하고 Wi-Fi에서 재개합니다. 셔플에서도 실제 다음 곡을 따르고 현재 곡 버퍼링 뒤에 시작하며 다운로드된 곡은 건너뛰고 일시 정지 중에는 멈춥니다. 다음 곡 앞부분 최대 16 MiB를 기존 서버/역할별 음악 캐시에 용량 제한 안에서 저장하고 재생 시 재사용합니다. 관리자 권한이 필요 없는 기기 설정입니다.

320–599 dp 휴대폰은 명시적인 2/3열 모드를 사용하며 더 좁은 창과 태블릿도 별도 열 수를 씁니다. 그리드 버튼은 숫자나 강조색 없는 중립 아이콘이고 화면 읽기 기능은 현재 열 수를 알립니다. 설정은 재시작 뒤에도 유지되며 라이브러리, 즐겨찾기, 장르 화면이 공유합니다. 라이브러리는 당겨서 새로 고침을 지원합니다. 큐는 현재 곡 위치에서 열리고 뒤로 가면 플레이어로 돌아가며 큐 비우기에는 확인이 필요합니다.

0.1.2는 재생 제어를 사용 가능한 안전 영역 안에 두고 남은 공간에 맞춰 표지를 조절합니다. 메타데이터는 곡 제목과 아티스트만 표시하고 제목을 누르면 앨범을 엽니다. 버퍼링 중에도 조작 가능한 재생/일시 정지 아이콘을 유지합니다. 곡 목록 셔플은 선택 토글이므로 Play all을 누르기 전에는 재생을 시작하거나 바꾸지 않습니다. 앨범 상세 셔플은 해당 앨범을 바로 재생합니다.

More → Cache settings는 음악/이미지 디스크 사용량, 128 MB–2 GB 음악 캐시 제한, 자동 음악/이미지 캐시 지우기를 제공합니다. 제한을 낮추면 오래된 음악 데이터를 즉시 내보내고 이미지는 별도 64 MB 제한을 사용합니다. 명시적 다운로드, 저장된 카탈로그, 로그인은 보존되며 활성 재생은 새 캐시를 만들 수 있습니다. 스트림 캐시 키에는 서버와 접근 역할이 포함됩니다.

즐겨찾기는 서버의 공유 선곡입니다. Web처럼 청취자와 게스트는 읽기만 가능하고 관리자만 수정합니다. 서버 URL, 카탈로그 스냅샷, 이미지, 다운로드는 서버/역할별로 분리합니다. 세션 쿠키는 Android Keystore AES-GCM으로 저장하고 암호는 저장하지 않습니다. 앱 데이터는 Android 백업에서 제외됩니다.

## 빌드 및 테스트

JDK 17과 Android SDK platform 35 / Build Tools 35.0.0을 사용하세요. Android Studio에서 이 디렉터리를 열거나 저장소 루트에서 실행합니다.

```powershell
android\gradlew.bat -p android testDebugUnitTest lintDebug assembleDebug assembleRelease
android\gradlew.bat -p android connectedDebugAndroidTest
```

macOS/Linux:

```sh
sh android/gradlew -p android testDebugUnitTest lintDebug assembleDebug assembleRelease
sh android/gradlew -p android connectedDebugAndroidTest
```

`ANDROID_HOME` 또는 무시되는 `android/local.properties`의 `sdk.dir`로 SDK를 지정하세요. 래퍼는 Gradle 8.9를 고정합니다. 테스트에는 운영 서버, 자격 증명, 음원이 필요 없습니다. JVM 테스트는 JSON 호환성, URL/쿠키 분리, 리디렉션 안전성, 다운로드 범위 검증을 확인합니다. 기기 테스트는 내장 HTTP 픽스처와 합성 PCM으로 네이티브 탐색, 재생, 탐색 위치 이동, 큐, 다운로드 및 오프라인 재생을 확인합니다.

출력:

- 설치 가능한 개발 APK: `app/build/outputs/apk/debug/app-debug.apk`.
- 서명되지 않은 release APK: `app/build/outputs/apk/release/app-release-unsigned.apk`. 배포 전에 자신의 릴리스 키로 서명하고 이후 업데이트에도 같은 키를 보관하세요.
- JVM/lint 보고서: `app/build/reports/`.

Android GitHub Actions 워크플로는 두 변형과 JVM/lint 검사를 실행하고 별도 API 35 에뮬레이터 작업을 수행합니다. 릴리스를 게시하거나 운영 키로 서명하지 않습니다.

검증 명령, 기록된 결과, 기기 범위 제한은 [검증 기록](VERIFICATION.ko.md)을 보세요. 대표 문서 스크린샷은 `docs/images/`에 포함합니다. APK, 전체 스크린샷 실행 결과, 빌드 보고서는 생성 산출물이며 소스에 포함하지 않습니다. CI 산출물은 워크플로 접근 권한이 필요하고 GitHub 보존 설정에 따라 만료됩니다.

## 현재 제한

재생 형식은 Media3와 기기 디코더에 따르며 일반 MP3, FLAC, AAC, WAV, Vorbis, Opus를 포함합니다. DSD/APE 등 전문 코덱은 내장하지 않습니다. 휴대폰 업로드는 회전에도 유지되지만 전경 편집 작업이므로 등록이 끝날 때까지 앱을 열어 두세요. 영구 백그라운드 업로드 큐가 아닙니다. 등록 전에 취소하면 저장소 제공자에서 부분 업로드를 정리해야 할 수 있습니다.

주요 청취 UI는 기기 언어에 따라 중국어와 영어를 제공하고 관리 화면은 현재 간체 중국어입니다. 브라우저 보조 RYM 갱신과 저장 HTML 가져오기, 전체 설정 백업/복원, 대량 저장소 이전, 저장소 OAuth 설정은 Web 앱에서 수행합니다. 이 클라이언트는 기존 서버에 연결하며 서버를 호스팅하지 않습니다.

저장소의 AGPL-3.0-only 라이선스를 따릅니다. 타사 의존성에는 각 라이선스가 적용됩니다. 내장 Shippori Mincho와 GenRyu Mincho는 Web과 같은 서체이며 SIL Open Font License는 `app/src/main/assets/licenses/`에 있습니다.
