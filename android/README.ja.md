# Android 版 Mihonban

[English](README.md) · [简体中文](README.zh.md) · [繁體中文](README.zh-Hant.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Français](README.fr.md) · [Español](README.es.md)

既存の Mihonban サーバーに接続する Kotlin / Jetpack Compose 製のネイティブクライアントです。WebView は使用しません。Android 8.0（API 26）以降が必要です。

## 接続

現在のプレビュー 0.1.10 をローカルでビルドするか、成功した [Android ワークフロー](https://github.com/hanfdev/mihonban/actions/workflows/android.yml)から debug APK を取得します。release APK には自分の署名鍵が必要です。サーバーのルートアドレス（例：`https://music.example.com`、`http://192.168.1.20:8788`）とリスナーまたは管理者のパスフレーズを入力します。空欄にできるのはサーバーがゲストアクセスを許可している場合だけです。Android エミュレーターからホストの開発サーバーには `http://10.0.2.2:8788` で接続できます。

リモートサーバーには HTTPS を推奨します。既存の Node/Wrangler 開発モードではローカル HTTP も使えますが、Cookie セッションのためサーバー側で `DEV_INSECURE_COOKIE=1` が必要です。TLS 証明書検証は省略しません。

## ネイティブ機能

- アルバムグリッド、曲一覧、ジャンル絞り込み、年／タイトル／アーティスト／評価／追加日時順、ライブラリ全体の検索、複数アーティスト表記、アーティスト別作品一覧。
- アルバム詳細、評価、説明、関連アルバム、内頁画像のページ切替とピンチズーム、Android 共有シート、アルバムと曲の共有お気に入り。
- ミニ／全画面プレーヤー、シーク、シャッフル、リピート、編集可能なキュー、次に再生、スリープタイマー、音声フォーカスとヘッドホン切断への対応。
- Media3 のフォアグラウンド再生サービスによる通知・ヘッドセット・ロック画面操作。画面がバックグラウンドになっても再生を続け、プロセス再起動後はキューを一時停止状態で復元します。
- WorkManager によるアプリ専用領域へのダウンロード、進捗、停止／再試行／削除、検証済みバイト範囲の再開、永続メタデータとカバー、オフライン再生、キャッシュ済みライブラリ閲覧。
- 管理者はアルバム／曲／アーティストの編集、表示切替、確認後の削除、Discogs のメタデータ・内頁取込、画像並べ替え、Android ファイル選択画面からの音声アップロード、サーバーフォルダーのスキャンと登録を行えます。
- サーバー管理：ゲストアクセスとモジュール設定、名前付きストレージの設定・テスト・書込先、R2 設定・テスト、ソース受信箱とスキャン、リスナー／管理者パスフレーズ変更。
- Web と同じ黒褐色の面、温かなアイボリー文字、朱色のアクセント、セリフ体見出し。タッチ領域、下部ナビゲーション、スクロール復元、システムの戻る、回転、インセットは Compose のネイティブ動作を使用します。

ライブラリはアルバムまたは曲を直接開きます。上へスクロールすると上部バーが隠れ、下へ戻ると再表示されます。グリッド密度を切り替えられ、ジャンルと並び順は閉じられるボトムシートにまとまっています。検索では既存ジャンル、最近追加したアルバム、結果カテゴリを表示します。アルバム詳細はカバーと情報を並べ、補助操作をメニューに集約します。タブ状態はサーバーとアクセス権限ごとに保存します。追加日時順にはアルバムの初回登録日時を使うため、評価やメタデータの編集で古いアルバムが先頭へ移動することはありません。

0.1.3 では説明文のインライン展開を専用リーダーに置き換えました。アルバムページにはプレーンテキストの 3 行抜粋を残し、リーダーの見出しと閉じるボタンは固定します。先頭へ戻る操作、閉じた際のアルバム位置復元、再度開く際の読書位置保持に対応します。CommonMark と GFM の表／取り消し線をネイティブ描画し、選択可能な文字、入れ子のリスト、引用、リンク、コード、区切り、独立画像を扱います。幅広い表とコードは横スクロールできます。生 HTML は無効なテキストとして表示します。WebView を使わず Web の配色と書体を維持します。

0.1.4 では説明画像の読込中表示、読める代替テキスト、画像再試行ボタンを追加し、失敗時の空白を解消しました。再試行はその画像だけを読み直し、リーダーを開いたままにします。使えない画像 URL には説明を表示し、成功しない再試行は提示しません。

0.1.5 では説明が 1 つの長い段落や引用の場合の「先頭へ戻る」を修正しました。Markdown ブロック内のスクロールも判定し、先頭に戻るとボタンを隠します。また Activity 再生成時にも見出しフォントを共有し、内蔵フォントバッファーの再確保を防ぎます。

0.1.6 では WorkManager ジョブ停止時に実行中のダウンロード要求をキャンセルします。サーバーがヘッダー前や本文転送中に停止していても対応し、停止／削除時にネットワークのタイムアウトを待ちません。カバー取得にも同じ処理を適用します。手動再試行は最初から開始し、自動再試行は検証済み部分データを再利用できます。

0.1.7 では文字やキャプションと同じ段落にある説明画像も表示します。入れ子の引用を含め、文字と画像を元の順序と読みやすい間隔で表示し、周囲の Markdown 書式を保持します。画像の読込表示と再試行も維持します。

0.1.8 では縦画面の再生操作を下端から離し、カバーをタイトルに近づけました。下部の補助行に現在の曲のダウンロード、共有、キューを配置します。ダウンロードは進捗と停止／再試行を提供し、完了ファイルを保持します。共有は曲名、アーティスト、Web アルバムリンクを Android の選択画面へ渡します。横画面では補助行をカバー下に置き、曲情報の領域を確保します。全画面プレーヤーのメタデータは引き続きタイトルとアーティストのみです。

0.1.9 では Web と同じ信頼度補正・同点処理を使う加重評価順を既定にしました。アルバムの主／副ジャンルを押すと、その順序の該当アルバムを開き、戻ると元のアルバムへ戻ります。上部バーを閉じるとタイトルとアイコンを完全にクリップし、システムのステータスバー領域を残します。

0.1.10 ではほぼ閉じた上部バーにタイトルやアイコンの断片が残る問題を修正しました。縮む帯の中央に操作を押し込むのではなく、完全な高さのバーを外へスライドさせ、実測した距離で閉じ、最後の部分をフェードさせます。表示倍率が変わっても閉じた位置を維持し、ステータスバー余白はスライド行の外に残します。

「More → Playback settings」の次曲プリロードには Wi-Fi のみ（既定）、常時、オフがあります。Wi-Fi のみでは既定ネットワークが携帯回線に変わると先読みをキャンセルし、Wi-Fi に戻ると再開します。シャッフル時も実際の次曲に追従し、現在の曲のバッファー確保後に開始、ダウンロード済み曲を除外、一時停止中は停止します。次曲の先頭最大 16 MiB を既存のサーバー／権限別音楽キャッシュに上限内で保存し、再生時に再利用します。端末設定なので管理者権限は不要です。

幅 320–599 dp の電話では明示的な 2／3 列モードを使い、より狭いウィンドウとタブレットも別の列数を使います。グリッド操作は数字や強調色のない中立的なアイコンですが、読み上げは現在の列数を伝えます。設定は再起動後も残り、ライブラリ、お気に入り、ジャンルページで共有します。ライブラリは引っ張って更新できます。キューは現在曲の位置で開き、戻るとプレーヤーへ移動し、全消去には確認が必要です。

0.1.2 では再生操作を利用可能な安全領域内に収め、残りの空間に合わせてカバーを縮放します。曲名とアーティストだけを表示し、曲名からアルバムを開けます。バッファリング中も操作可能な再生／一時停止アイコンを残します。曲一覧のシャッフルは選択切替で、「Play all」を押すまでは再生を開始・変更しません。アルバム詳細のシャッフルはそのアルバムを直ちに再生します。

「More → Cache settings」では音楽／画像のディスク使用量、128 MB–2 GB の音楽キャッシュ上限、自動音楽／画像キャッシュの消去を提供します。上限を下げると古い音楽データを直ちに削除し、画像には別の 64 MB 上限を使います。明示的ダウンロード、保存済みライブラリ、ログインを保持しますが、再生中は新しいキャッシュが作られる場合があります。ストリームキャッシュキーにはサーバーと権限を含めます。

お気に入りはサーバー共有の選集です。Web と同じくリスナーとゲストは閲覧のみ、管理者だけが変更できます。サーバー URL、ライブラリのスナップショット、画像、ダウンロードをサーバーと権限で分離します。セッション Cookie は Android Keystore の AES-GCM で保存し、パスワードは保存しません。アプリデータは Android バックアップ対象外です。

## ビルドとテスト

JDK 17 と Android SDK platform 35 / Build Tools 35.0.0 を使用します。Android Studio でこのディレクトリを開くか、リポジトリのルートから実行します。

```powershell
android\gradlew.bat -p android testDebugUnitTest lintDebug assembleDebug assembleRelease
android\gradlew.bat -p android connectedDebugAndroidTest
```

macOS/Linux：

```sh
sh android/gradlew -p android testDebugUnitTest lintDebug assembleDebug assembleRelease
sh android/gradlew -p android connectedDebugAndroidTest
```

`ANDROID_HOME` または Git 対象外の `android/local.properties` の `sdk.dir` で SDK を指定します。ラッパーは Gradle 8.9 に固定されています。テストに本番サーバー、認証情報、音声ファイルは不要です。JVM テストは JSON 互換性、URL／Cookie 分離、リダイレクトの安全性、ダウンロード範囲検証を対象とします。端末テストは内蔵 HTTP フィクスチャーと合成 PCM 音声でネイティブ操作、再生、シーク、キュー、ダウンロード、オフライン再生を確認します。

出力：

- インストール可能な開発 APK：`app/build/outputs/apk/debug/app-debug.apk`。
- 未署名 release APK：`app/build/outputs/apk/release/app-release-unsigned.apk`。配布前に自分のリリース鍵で署名し、以後の更新用に同じ鍵を保管します。
- JVM と lint のレポート：`app/build/reports/`。

Android GitHub Actions は両ビルドと JVM／lint 検査を実行し、別の API 35 エミュレータージョブも実行します。自動リリース公開や本番鍵による署名は行いません。

検証コマンド、記録された結果、端末検証範囲は[検証記録](VERIFICATION.ja.md)を参照してください。代表的な文書用画像は `docs/images/` に保存します。APK、全スクリーンショット、ビルドレポートは生成物としてソースに含めません。CI 成果物にはワークフローへのアクセスが必要で、GitHub の保持設定に従い期限切れになります。

## 現在の制限

再生形式は Media3 と端末のデコーダーに依存し、一般的な MP3、FLAC、AAC、WAV、Vorbis、Opus を含みます。DSD/APE などの専用コーデックは内蔵しません。電話からのアップロードは回転に耐えますが前面の編集操作なので、登録完了までアプリを開いてください。永続バックグラウンドアップロードキューではありません。登録前の中止では、ストレージ側の部分ファイルの清掃が必要な場合があります。

主な音楽画面は端末言語に応じて中国語と英語を表示し、管理画面は現在簡体字中国語です。ブラウザー補助 RYM 更新と保存 HTML 取込、完全な設定バックアップ／復元、一括ストレージ移行、ストレージ OAuth 設定は Web を使用します。このクライアントは既存サーバーに接続し、サーバーをホストしません。
